### Done

- **Navigation order** (§2): Content, Pages, Company, Media, Sales, Settings, System, in the
  sidebar and on the dashboard home.
  - Payload lists every collection before any global, so "Pages" (globals only) cannot come second
    from configuration alone.
  - `src/admin/AdminNav.tsx` is Payload's default nav, built from the client pieces Payload
    exports, with the groups sorted by `src/admin/navGroups.ts`.
- **Language switch** (§1): `src/components/admin/AdminLanguageToggle.tsx`, always visible in the
  header. The owner reported "واجهة لوحة التحكم العربية لاتعمل": Arabic worked, but Payload's own
  switch is on the Account page only.
- **Arabic labels** (§1): the one field without a label (`users.email`) now has one.
  `src/admin/arabicLabels.test.ts` walks every collection, global, field and option the staff see
  and fails on a missing Arabic label.
- **Dashboard home** (§4): `src/admin/AdminDashboard.tsx` replaces the default dashboard view.
  - Quote requests by status (new, contacted, quoted) for the last 7 days, and failed e-mails.
  - Drafts waiting to be published, scheduled publishes, the last 5 edited items, quick links.
  - Then every section the viewer may open, in the group order.
  - The data comes from `src/admin/dashboardData.ts`: every read is a Local API call with
    `overrideAccess: false` and the viewer as `user`. A read the viewer may not make hides its card.
- **Role visibility** (§4): `users` and `site-settings` are listed for admins only
  (`admin.hidden`). The e2e found that an editor saw both.
- **Live Preview** (§3): `src/admin/livePreview.ts`, for `projects`, `services` and the six page
  globals, with the breakpoints 1440 / 768 / 390.
  - The URL is the existing `/api/preview` route (P3-T1 §7): it checks the secret and the staff
    session, turns draft mode on and redirects to the page.
  - `src/components/LivePreviewRefresh.tsx`: the public layout renders it only in a staff draft
    preview. It answers Payload's `payload-document-event` with `router.refresh()`, on the same
    origin and only for the window that embeds or opened the page.
  - The secret derivation moved to `src/previewSecret.ts` so that `payload.config.ts` can use it;
    `src/lib/preview.ts` re-exports it.
- **Branding** (§5): logo and icon from `public/brand/`, title suffix, favicon, light theme, brand
  colours in `src/app/(payload)/custom.scss` through CSS variables and our own classes.
- **API tab hidden** on every edit view (`admin.hideAPIURL`). It hides the tab only; access rules
  are unchanged.
- **Quote request phone** (§5b): `src/components/admin/QuotePhone.tsx` shows it grouped
  (`+966 57 353 4185`) in the list and the edit view. The stored value stays E.164; a number that
  is not a KSA one shows as stored.
- **Arabic RTL** (§6): in a right-to-left page the rich-text editor's parked menus made every edit
  view scroll sideways. The root no longer scrolls sideways in RTL (`custom.scss`).
- **Login-hardening tests** (§7, carried from the P2-T9 review):
  - `src/security/loginEnumeration.dummyHash.test.ts`: a spy on the real PBKDF2 call. It fails
    when the dummy hash call is removed.
  - `tests/int/p2-t7-login-race.int.test.ts`: reaches `LockedAuth` inside `loginOperation`
    (the hook's own lookup is answered with the state from just before the lock) and checks the
    masked 401, byte for byte, in Arabic and English.

### Security notes

- **Z1:** no new collection or global. `users` and `site-settings` gain `admin.hidden` for
  non-admins; this hides them in the admin only and changes no access rule.
- **Z2, I1:** Live Preview goes through the existing `/api/preview` route. The URL carries the
  preview secret, as P3-T1 designed it; the route still requires a staff session.
- **S4:** `src/previewSecret.ts` has no `import 'server-only'`, for the same reason as
  `src/env.ts`: the Payload CLI runs the config under plain Node. No client component imports it;
  `local/no-server-in-client` and the CI client-bundle grep cover it. *For review.*
- **H3:** no CSP change. The admin CSP already allows a same-origin frame, and the public pages
  already send `frame-ancestors 'self'`.
- **A1, A5:** the two login-hardening tests of §7.
- The dashboard home reads `payload-jobs` (scheduled publishes) with the viewer's access. A viewer
  who may not read it does not get the line.

### Deviations from spec

- **"Arabic first" (§1) is not the default language.** `i18n.fallbackLanguage` stays `'en'`.
  - `tests/int/p3-t12.int.test.ts` pins it to `'en'` (owner decision 2026-10-24).
  - The dashboard opens in English and turns Arabic with the header switch; the choice is kept.
- **The browser's language is not followed.** A request with `Accept-Language: ar` still gets the
  English dashboard. The cause was not found. Payload's `getRequestLanguage` reads that header, so
  this was expected to work.
- **Server components live in `src/admin/`,** not `src/components/admin/`: the lint rules forbid
  Payload runtime imports under `src/components/`.
- **One existing test file changed:** `src/p3-t12-arabic-switch.test.ts`. Its `next/navigation`
  mock gains `useRouter`, because the layout now renders `LivePreviewRefresh`. No assertion
  changed. *For review.*
