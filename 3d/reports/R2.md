# R2 — Look-dev + first real-time export

> **Paths:** since R3a the project lives at `C:\aljazira-3d` (the S: share is offline). Read every `S:\...` path below as `C:\...`.

Built in Blender 5.2.3 through the blender MCP tools, plus background Blender jobs for every render and export. The only external asset is the Poly Haven HDRI *Qwantani Dusk 2 (Pure Sky)* (CC0). No generators.

3. **interior_opacity**
   - It is a custom property on the `ARCH_core` root Empty, same pattern as `facade_opacity`.
   - Slabs are now **one object per level** (`CORE_slab_GF`, `L01`…`L22`, `RF`).
   - Each `SYS_<s>` root carries `floor_slabs` (glTF extras), which lists the slabs that stay opaque: hvac `RF,L22`; fire, plumbing and power `GF`; smart `L01`.
4. The podium-corner mismatch is accepted.
5. **Backdrop**
   - Low blocks, plus a **dusk gradient sky dome** (`CTX_skydome`, emissive, 576 tris, radius 2.6 km, with a warm sunset lobe on the right of the hero view).
   - Plus a **ground disc with a night city-lights texture**, which reads as far city under the fog.
   - Fog is done in code on the web. For the offline render it is faked with a camera-distance haze on the far materials, a render-only override that is never saved or exported.
   - Suggested web fog: `FogExp2(0x3C485D, ~0.0006)`. Set `fog: false` on the sky-dome material.

Also, to support real-time sorting (see below):
- The **curtain wall is split into 4 objects by orientation** (`FAC_cw_S/E/N/W`).
- **Every mesh's origin is moved to its bounds centre**. All origins were at (0,0,0), and Three.js sorts transparent objects by origin.
- A gold **crown light line** (`FAC_crown_light`) was added. The crown band itself is now navy glass, like the reference.

## Materials (glTF-PBR only: Principled BSDF + image textures)
| Material | Notes |
|---|---|
| `MAT_glass_cw` | Navy reflective glass (metallic 0.6, roughness 0.06). Emissive texture `tex_cw_emit` (2048×1536: 64 modules × 24 floors). Per-floor lit/unlit variation, warm/cool cells, ceiling-light gradient, dark spandrels, and a navy self-glow that lightens toward the top so the glass reads blue in real time without reflections. **BLEND**, double-sided. |
| `MAT_mullion`, `MAT_gold_fin`, `MAT_crown_glass`, `MAT_crown_light`, `MAT_podium_glass` | Façade, **BLEND**. Fins are champagne gold (#C8963E) with a slight warm emission. The crown light is #EFCB76 at strength 25. The podium uses a warm lobby-glow texture. |
| `MAT_concrete` | Slabs + core, **BLEND**, double-sided (fades with `interior_opacity`) |
| `MAT_gold_podium`, `MAT_stone`, `MAT_paving`, `MAT_asphalt`, `MAT_planting`, `MAT_palm_*`, `MAT_lamp_*` | Opaque. Lamp heads are emissive. |
| `MAT_city` | Base and emissive window textures (512², 24 m tile), box-mapped UVs, plain roofs |
| `MAT_sky`, `MAT_ground` | Emissive-only gradient sky / city-lights carpet |
| `MAT_<s>_metal` ×5 | Neutral metal by default (one material per system, so code can address each one) |
| `MAT_<s>_highlight` ×5 | Gold #DFA82A, emissive #DFA82A at 1.0. Exported as **KHR_materials_variants** `highlight_<s>`: switching the variant swaps every mesh of that system. Three.js: `GLTFLoader` → `gltf.functions.selectVariant(scene, 'highlight_fire')`, and `null` to reset. |

`alphaMode BLEND` note: Blender's exporter only writes BLEND when the alpha factor is below 1, so the façade and interior materials export with **baseColorFactor alpha 0.999** (visually opaque). The code can then set `material.opacity` freely.

## Lighting and baking
- **Offline (Cycles)**
  - The HDRI is rotated 71° so its sunset glow sits on the right of the hero view, at strength 0.2. AgX Medium High Contrast.
  - 11 warm point lights in the plaza lamps (`LIGHTS`, render-only, not exported).
- **GLB**
  - **Ambient occlusion is baked into one atlas per collection group** on a dedicated `LM` UV, wired into the standard glTF **occlusionTexture**:

    | Atlas | Size | Objects | Bake time |
    |---|---|---|---|
    | `LM_arch` (façade + core + podium) | 2048² | 37 | 91 s |
    | `LM_systems` | 1024² | 19 | 64 s |
    | `LM_site` | 1024² | 6 | 10.5 s (roads and ground disc excluded) |
    | `LM_context` | 1024² | 1 | 5 s |

  - The occlusion texCoord is 1 where the mesh also has a texture UV, and 0 otherwise. GLTFLoader sets the AO channel itself.
  - Night lighting comes from the emissive textures plus an environment map. Use the same HDRI as a 1K PMREM environment in Three.js.
  - I did **not** bake a full diffuse lightmap: glTF has no standard slot for one, and AO + emissive + env already gives the look (see the real-time comparison). If you want one, I can bake `LM_*_light` atlases and reference them in node extras for `material.lightMap` in R3.

## Real-time test export
- `web\tower_r2_test.glb`: **2.61 MB, 10,838 triangles**, 66 meshes, 117 nodes, 29 materials, 10 images (JPEG q90, at most 2048²). Draco OFF.
- Extensions: `KHR_materials_emissive_strength`, `KHR_materials_variants`.
- 6 cameras: CAM_hero yfov 31.76°; the system cameras are 62–69°.
- Extras: `facade_opacity`, `interior_opacity`, `floor_slabs`, and the HOT_ `label`s.
- Full `gltf-transform inspect` output: `web\inspect_tower_r2_test.md`.
- Texture payload: LM_arch 577 KB, tex_cw_emit 386 KB, LM_systems 262 KB, LM_context 257 KB, LM_site 128 KB, the rest under 100 KB each. Estimated GPU memory before KTX2: about 67 MB.
- **Budgets**
  - tower.glb (≤ 8 MB / 150k tris): OK.
  - tower-lite (≤ 2.5 MB / 50k): tris OK, but the size is **0.11 MB over** before compression. KTX2 + meshopt in R3 brings it well under. Alternatively, the lite version can drop `LM_arch` to 1K and leave out `LM_context`.
- `renders\r2\realtime_hero.png`: EEVEE render of the **GLB alone** (fresh empty Blender, glTF import, same HDRI as the environment, CAM_hero with shift −0.227 re-applied).
  - Framing is identical to Cycles, and look and colour hold up.
  - Differences: no fog and no lamp light pools (both render-only), and the +X mullions read brown under EEVEE's lighting.
- **Lens shift:** glTF has no shift, so CAM_hero needs `setViewOffset` (+0.227·H, as you expected).

## Transparency sorting (façade 0.15, interior 0.4)
- A 24-frame EEVEE orbit of the GLB (EEVEE sorts blended objects per object, like Three.js) showed **no popping or flicker** between neighbouring frames, once every object had its own origin. With all origins at 0,0,0 it would have been arbitrary. **No clipping planes needed so far.**
- **Readability issue (design, not sorting):**
  - From a distance, 24 stacked slabs at 40% plus double-sided emissive glass at 15% read as a milky block.
  - From the system entry cameras the equipment reads well. I compared interior 0.4 and 0.15 from CAM_fire: almost no difference, because the haze is mostly the glass.
  - Recommendation for the web:
    - when a system is entered, also scale the façade `emissiveIntensity` down to about 0.3;
    - use `depthWrite = false` on BLEND materials;
    - consider interior 0.25.

## Issues / notes
- Blender glTF add-on bug: setting a material-variant name from Python recurses in the add-on's name-update callback and crashes Blender (stack overflow). `export_glb.py` works around it. Exports run with `--factory-startup`, so the user's Blender preferences are never changed.
- `npx @gltf-transform/cli@4` was fetched on first use (npm cache only; nothing was installed into the project).
- Time: about 41 min wall-clock for R2 (17:13 → 17:54 by the Blender session clock), including about 12 min of background renders.
