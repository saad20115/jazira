# P2-T5 — Globals

Phase 2 · branch `phase-2-content` · specs: `docs/02-content-model.md` Globals + **Addendum**
(field lists per section) · security: Z1, Z2, I3

## Scope
1. Reusable groups in `src/fields/groups/`: `cta`, `pageHeader`, `sectionIntro`, `pillar`,
   `button` (label + `linkField`).
2. Globals: `site-settings` (update admin only), `navigation` (admin + editor), `home-page`,
   `services-page`, `about-page`, `projects-page`, `contact-page`, `privacy-page` — every field
   from the Addendum, every page section with `enabled`. Page globals are **publishable**
   (drafts + autosave + schedule) and readable publicly only when published.
3. `navigation`: header links and footer columns using `linkField`; max lengths; order by array
   order.
4. Admin: each global under group "Pages" or "Settings"; sections as collapsible groups in Figma
   order with Arabic titles that match what the editor sees on the site (e.g. "قسم من نحن").
5. Revalidate hooks per global (which paths/tags each one invalidates — document it).
6. Migration.

## Evidence required
- Tests: anonymous REST `GET /api/globals/home-page` returns the **published** version only while a
  newer draft exists; editor cannot update `site-settings`; admin can.
- Admin screenshots (Arabic) of `home-page` (all sections collapsed + one expanded) and
  `site-settings`.

## Acceptance criteria
- [ ] Every editable thing in the design has a field (cross-check against `design/copy/` — attach
      the checklist: each copy line → field path or "i18n").
- [ ] Draft/published behaviour for page globals proven (Z2).
- [ ] `site-settings` admin-only update proven.
