# P3-T11 — Live 3D model viewer (real-time)

Phase 3 · branch `phase-3-frontend` · depends on: P3-T5 **and** asset task `A-1` delivering the
web model · specs: `docs/05-design.md` §"CTO decisions" §16

Start only when `public/systems/<version>/model/` contains the GLB delivered by A-1. Until then
this task is `BLOCKED` on A-1 — skip it and continue (it is not a hard stop for the rest).

## Scope
1. "Open the live 3D model" opens a full-screen dialog (focus trap, Esc closes) with a Three.js
   viewer of the **same** tower used for the cinematic shots: GLB with meshopt/Draco geometry
   and KTX2 textures, **baked lighting** (lightmaps from Blender) so it looks close to the
   renders without real-time shadows; `three` pinned exact, loaded only when the dialog opens.
2. Orbit (pointer + touch), zoom limits, auto-rotate when idle; layer toggles for the 5 systems
   (meshes named by system in the GLB) — selecting one ghosts the façade and highlights that
   system in gold, camera eases to the same viewpoint as its cinematic shot.
3. Device gate: WebGL2 + `deviceMemory ≥ 4` + not `saveData`; otherwise the button opens the
   cinematic explorer (P3-T5) in full screen instead.
4. DPR cap 1.5, render on demand, dispose everything on close (heap snapshot before/after 5
   open/close cycles in the report).
5. Budgets: model + textures ≤ 8 MB total, first frame ≤ 3 s on a mid-range phone over 4G
   (Lighthouse/WebPageTest trace), no impact on the page underneath.

## Acceptance criteria
- [ ] Viewer code and assets load only after the button is pressed.
- [ ] System toggles match the cinematic shots' viewpoints.
- [ ] Weak devices get the cinematic fallback, never a broken canvas.
- [ ] No memory growth across open/close cycles.
