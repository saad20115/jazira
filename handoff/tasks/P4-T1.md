# P4-T1 — Materials + brands seed (73 rows)

Phase 4 · branch `phase-4-seed` · specs: `docs/02-content-model.md` "Seed data rules" · source:
`seed/materials.raw.json`

## Scope
1. `pnpm seed` entry (never run automatically, refuses to run when `NODE_ENV=production` unless
   `--force-production` is passed explicitly).
2. Parse `seed/materials.raw.json` verbatim; split multi-brand cells (`/`, `|`, `,`); normalize with a
   **mapping table in code** containing exactly the typos listed in the spec plus case/whitespace
   normalization; anything else uncertain is left as-is and reported.
3. Brands: upsert by normalized `name`; `origin` from `originRaw` (per-brand where the cell has
   `Brand: Country` pairs), translated to Arabic country names via a fixed table.
4. **Rows 58–73** (structural/architectural): the origin column holds a second supplier, not a
   country — seed both as brands with `origin` empty, mark them for client review.
5. Materials: upsert by `itemNo`; English `description` normalized to Title Case as in the design
   table ("EMT Conduit"); Arabic `description` drafted and marked `needsClientReview` in the report.
6. Idempotent: running twice changes nothing (compare counts and `updatedAt`).

## Evidence required
- Output of two consecutive runs (second run: 0 created, 0 updated).
- Counts: 73 materials, N brands; every material has ≥ 1 brand (query output).
- Report tables: every normalization applied (raw → normalized, row numbers); every row needing
  client confirmation (incl. 58–73); every Arabic draft string.

## Acceptance criteria
- [ ] Idempotent (proven).
- [ ] 73 materials, each linked to ≥ 1 brand; per-system counts match the design (20 / 37 / 8 / 8
      — explain any difference with the raw file).
