# P3-T12 — English default + admin "Arabic on/off" switch

Phase 3 · branch `phase-3-frontend` · owner decision 2026-10-24 · specs: `docs/01-architecture.md`
(Localization, "Arabic switch"), `docs/02-content-model.md` (`site-settings.arabicEnabled`), AGENTS.md
Hard rules. **Order:** after P3-T4 r3 is submitted, before P4-T2.

> Owner: the site is English by default. Arabic is available but switched off, and it can be switched
> on later from the admin panel.

## Scope
1. **Default locale `en`.**
   - Payload `localization.defaultLocale: 'en'`.
   - `src/i18n` `DEFAULT_LOCALE = 'en'`.
   - `/` → `/en`.
   - Admin default language `en` (`DEFAULT_ADMIN_LANG`), with `ar` still selectable.
   - Check every place that assumed `ar` first: fallbacks, `x-default`, sitemap, seed order, tests,
     evidence scripts.
2. **`site-settings.arabicEnabled`**
   - A checkbox, default `false`, update admin-only (field-level access), read public.
   - Add it with a migration. Existing rows get `false`.
   - The admin label and description are in both languages.
3. **Arabic switched off** (the default):
   - `/ar` and `/ar/*` give a **307** to the same path under `/en`, keeping the query string.
   - No language switcher, in the header or the footer.
   - `hreflang`: `en` + `x-default` → `/en`.
   - `sitemap.xml`: `en` only.
   - The JSON-LD and OG `locale` are `en`.
   - `/api` and `/admin` are unaffected. Editors can still edit and preview Arabic: **Live Preview
     and draft preview of `ar` work for logged-in editors while the switch is off.**
4. **Arabic switched on:** exactly today's bilingual behaviour, with `ar` added to hreflang and the
   sitemap and the switcher shown.
5. **No redeploy.** Saving `site-settings` revalidates the affected tags and paths, and the next
   request reflects the switch. The flag is read through a cached, tagged call: never one DB query
   per request, and never from the client.
6. **Tests** (unit, integration and e2e):
   - off → 307 and no switcher;
   - on → 200 and the switcher;
   - toggle → live after save;
   - an editor cannot change the flag, only an admin can;
   - the sitemap and hreflang in both states.

   All existing `ar` tests keep running with the flag **on**: Arabic stays fully tested.

## Acceptance criteria
- [ ] A fresh DB with the switch off: `/` → `/en`, `/ar` → 307 `/en`, and no Arabic is reachable by
      an anonymous visitor (crawl every link on `/en`).
- [ ] An admin turns it on and saves. Within one request `/ar` gives 200 RTL and the switcher shows.
      Turning it off reverts.
- [ ] An editor gets 403 or a read-only field for `arabicEnabled`.
- [ ] Every existing test passes, plus the new ones. DoD in full.
- [ ] Evidence:
  - a `curl -I` log for both states;
  - screenshots of the admin field and of `/en` with and without the switcher (1440 and 390);
  - the sitemap for both states.

## Notes
- This does **not** remove any Arabic work. RTL, Noto Kufi and the Arabic drafts stay.
- P4-T2 seeds `arabicEnabled: false`.
