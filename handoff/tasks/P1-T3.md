# P1-T3 — Access helpers, `users` (auth hardening), `media` (upload safety)

Phase 1 · specs: `docs/02-content-model.md` (Roles, `users`, `media`), `docs/04-phases.md` Phase 1
items 6, 7 · security: A1–A6, Z1 (users/media), Z3, I5

Start only after P1-T2 is `ACCEPTED`.

## Scope
1. **`src/access/`** — `isAdmin`, `isAdminOrEditor`, `publishedOrLoggedIn`, `isAdminFieldLevel`,
   plus an `adminOrSelf` helper for users. One unit test file per helper covering anonymous,
   editor and admin.
2. **`users`** (group: System) — fields `name`, `role` exactly as in the content model.
   - Access: read — admin all, editor self only; create/delete — admin; update — admin or self.
     `role` field: create **and** update = admin only (Z3).
   - First user created through Payload's first-user flow becomes `admin`; every later user
     defaults to `editor`. No public registration (A6). Verify how 3.91's first-register route
     interacts with `create: isAdmin` and describe it.
   - A1 `maxLoginAttempts: 5`, `lockTime` 15 min.
   - A2 `tokenExpiration: 7200`; server-side sessions kept on. **Verify and document** in the
     report: after logout, and after an admin removes a user's sessions, the old token is
     rejected (show the request and the 401).
   - A3 cookies `secure` in production, `sameSite: 'Strict'`, httpOnly; `useAPIKey: false`.
   - A4 password policy enforced server-side on create, update and reset: min 12 chars and not in
     a small bundled common-password list (no network call).
   - A5 forgot-password: token expiry ≤ 1 h; identical response for existing and unknown email.
     For local dev, deliver mail to a local catcher (e.g. Mailpit in the dev compose, image pinned
     by digest) through `@payloadcms/email-nodemailer@3.91.0`. Production SMTP is Phase 5.
     Both additions go in the report's Dependencies section. If you think the catcher is not
     needed, say why and how you proved A5 instead.
3. **`media`** (group: Media) — exactly as in the content model: `mimeTypes` image/jpeg, png,
   webp, avif only; **no SVG**; max 10 MB; `focalPoint`; image sizes `thumb` 400w, `card` 800w,
   `hero` 1920w, `og` 1200×630 crop, output webp; `alt` (localized, required), `caption`
   (localized). Access: read public; create/update/delete admin + editor.
   - I5: file type checked from **content (magic bytes)**, not extension or client MIME. Check
     what 3.91 already does; add a hook only for what is missing, and say which.
   - Filenames sanitized (no path segments, control chars, or leading dots).
   - Upload folder is not served from `public/`.
4. **Integration tests** (Vitest, real Postgres test DB from P1-T2, through REST and Local API
   with `overrideAccess: false`):
   - first user → admin; admin creates editor; editor `PATCH /api/users/:id {role:'admin'}` on
     self → role unchanged or 403; editor cannot create users; anonymous cannot list users
   - 6th wrong password locks the account (and the right password is refused while locked)
   - password `short` and a common password are rejected; a strong one is accepted
   - forgot-password response identical for known and unknown email
   - upload `.svg` → rejected; HTML file renamed `.jpg` → rejected; real JPEG → accepted with
     all four sizes generated as webp; anonymous upload → 403

## Evidence required in the report
- `pnpm test` full output (test names visible)
- The session-revocation check from A2 (requests + status codes)
- Screenshot of the admin users list and a media item with sizes (`docs/reports/phase-1/`)
- `pnpm lint`, `pnpm typecheck`

## Acceptance criteria
- [ ] `users` and `media` have explicit `read`/`create`/`update`/`delete` access (Z1).
- [ ] All tests listed in Scope §4 exist and pass against Postgres.
- [ ] Editor cannot escalate role by any route (REST, Local API with `overrideAccess: false`).
- [ ] Lockout after 5 failures, 15 min lock.
- [ ] Logout and forced logout revoke the token (A2), demonstrated.
- [ ] SVG and disguised HTML uploads rejected by content check.
- [ ] Password policy enforced server-side on create, update and reset.
