# P5-T1 — Quote server handler, anti-abuse, email notification

Phase 5 · branch `phase-5-quotes` · specs: `docs/01-architecture.md` §5, `docs/04-phases.md`
Phase 5 · security: I1, I6, Z4, D2, S1, S4

## Scope
1. Replace the P3-T9 stub with the real server action (or route handler — say which and why):
   parse with the shared zod schema (strip unknown keys, length limits), honeypot must be empty,
   form filled in ≥ 3 s, rate limit per `ipHash` (3/min, 20/day) stored in Postgres (no in-memory
   store — survives restarts and multiple instances), consent must be true.
2. On success: create the `quote-requests` doc via Local API with `overrideAccess: true` (comment
   why), `odooStatus: 'pending'`, then enqueue the Odoo job (P5-T2 provides the task; until then
   enqueue a no-op task). The visitor sees success **as soon as the save succeeds**.
3. Generic messages only: success, "check the form", "too many attempts, try later". No internal
   details, no stack traces.
4. Email notification to the sales inbox via `@payloadcms/email-nodemailer@3.91.0` (already used
   for A5); Mailpit in dev; template in Arabic + English with only the fields needed; failure to
   send is logged (IDs only, D2) and never fails the request.
5. Env: SMTP vars and `SALES_INBOX` added to `src/env.ts` (required in production, optional in dev).
6. Optional Cloudflare Turnstile behind a flag (`TURNSTILE_ENABLED`), off by default — implement
   only the switch and server verification; do not enable it.

## Evidence required
- Tests: valid submit → doc created + job enqueued; honeypot filled → generic success but **no doc**;
  submitted in < 3 s → rejected; 4th submit within a minute → rate-limited; unknown keys stripped;
  over-long fields rejected; consent false → rejected; REST `POST /api/quote-requests` still 403.
- Mailpit screenshot of the notification email (ar + en).
- `pnpm test`, lint, typecheck, build.

## Acceptance criteria
- [ ] All tests above pass; rate limit persists across a server restart (demonstrated).
- [ ] No PII in logs (grep the dev log after a test run).
- [ ] Visitor never sees an error after a successful save.
