# P2-T4 — `projects`

Phase 2 · branch `phase-2-content` · specs: `docs/02-content-model.md` `projects` + Addendum ·
security: Z1, Z2, I2, I3, I4

## Scope
1. `projects` (group Content, **publishable** incl. scheduled publish) with every field from the
   model and the Addendum: `title`, `slug`, `category` (5 design options), `client`, `location`,
   `year` (1990…current+2), `status`, `scope` (hasMany, 8 options), `scopeSummary`, `deliveredBy`,
   `summary` (max 280), `body` (limited Lexical, same config object as services — reuse it),
   `details` (accordion pillars, max 8), `deliverables` (max 10), `coverImage` (required),
   `gallery` (max 30), `video` **xor** `videoUrl` (validation: not both), `featured`, `order`,
   `meta`.
2. Admin: list columns title, category, status, featured, `_status`, updatedAt; filters by
   category/status/featured; sidebar for slug/order/featured/status; tabs "Content / Media /
   Details / SEO" so editors are not overwhelmed.
3. Revalidate hooks: project page, projects list, home (if `featured` changed), related projects.
4. Migration.

## Evidence required
- Tests: draft never returned to anonymous (REST and Local API `overrideAccess: false`); scheduled
  publish job publishes at the set time (use a short schedule in the test); `video` + `videoUrl`
  together rejected; `videoUrl` on a non-allowed host rejected; slug auto-generated and unique.
- Admin screenshots (Arabic) of the edit view tabs and the list.

## Acceptance criteria
- [ ] All fields exist with the specified validation and localization.
- [ ] Scheduled publish works (tested).
- [ ] Revalidation tags documented (which change invalidates which page).
