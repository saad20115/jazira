# P2-T3 — `services`, `team`

Phase 2 · branch `phase-2-content` · specs: `docs/02-content-model.md` + Addendum ·
security: Z1, Z2, I2

## Scope
1. `services` (group Content, **publishable**) — `title` (L), `slug`, `tier` (`main|additional`),
   `featured`, `icon` (the 10 options from the Addendum, admin shows the icon next to the label via
   a small custom field component), `shortDescription` (L, max 200), `highlights` (array max 6),
   `body` (L, Lexical with the limited feature set from the model — h2–h4, bold, italic, lists,
   link (I3 rules), upload (media), blockquote; nothing else), `image`, `order`, `meta` (SEO plugin
   `@payloadcms/plugin-seo@3.91.0`).
2. `team` (group Company) — exactly as the model: `tier`, `photo` required for leadership only
   (conditional validation), `bio` only for leadership (`admin.condition`), `linkedin` validated to
   `linkedin.com`, `order`, `active`.
3. Read access: `services` uses `publishedOrLoggedIn`; `team` public read returns only
   `active: true` for anonymous users.
4. Arabic/English labels, descriptions, columns, groups; revalidate hooks; migration.

## Evidence required
- Tests: anonymous never sees draft services; anonymous never sees inactive team members;
  leadership without photo is rejected; staff without photo is accepted; Lexical rejects a
  disallowed node (e.g. raw HTML / iframe) on save.
- Admin screenshots (Arabic) of a service edit view (icon picker visible) and a team edit view.

## Acceptance criteria
- [ ] Draft/published behaviour proven for `services` (Z2).
- [ ] Lexical feature set limited exactly as specified (list the enabled features in the report).
- [ ] Conditional fields and validation for `team` tested.
