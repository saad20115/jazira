# P7-T2 — Operations runbook and final project report

Phase 7 · branch `phase-7-handover`

## Scope
1. `docs/runbook-ops.md`: local setup from zero; running tests; adding a migration; deploying;
   rollback; backup/restore; rotating every secret (PAYLOAD_SECRET, IP_HASH_SALT, DB password,
   SMTP) and what each rotation breaks (sessions, rate-limit hashes…); updating
   dependencies (grouped `@payloadcms/*`, how to read the audit, when the CTO must approve a
   major); incident checklist.
2. Credentials handover checklist (what exists, where it lives, who holds it) — names only, never
   values.
3. `docs/reports/final.md`: what was delivered per phase, every security item S/A/Z/I/H/D/B/R/O
   with status and proof link, open items (hard stops, `needsClientReview` lists, deferred
   minors), known limitations.

## Acceptance criteria
- [ ] A fresh clone can be set up and run by following the runbook literally (the CTO will do it).
- [ ] Every security ID appears in the final report with a status.
