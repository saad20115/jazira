# P1-T2 — Env validation, Payload & Next config, dev DB

Phase 1 · specs: `docs/01-architecture.md` §3, `docs/04-phases.md` Phase 1 items 3, 4, 5, 8 ·
security: S1, S2, S3, S4, H1, H2 (no HSTS), H4, H7

Start only after P1-T1 is `ACCEPTED`.

## Scope
1. **`docker-compose.dev.yml`** — Postgres **18.x**, image pinned by tag **and digest**, named
   volume, port bound to `127.0.0.1` only, healthcheck, credentials from `.env` (no defaults
   like `postgres/postgres`). Create a second database for tests (e.g. `aljazira_test`) so tests
   never touch the dev DB. The app connects as a dedicated DB user, not the superuser (D1 spirit).
2. **`src/env.ts`** (S1, S2, S4) — zod 4 schema, validated once at startup:
   `DATABASE_URL`, `PAYLOAD_SECRET`, `SERVER_URL` (absolute http(s) URL), `IP_HASH_SALT`.
   - `PAYLOAD_SECRET` and `IP_HASH_SALT`: at least 48 characters, must differ from each other,
     and must not equal the placeholder values in `.env.example`.
   - Error message names the missing/weak variable and how to generate one
     (`openssl rand -base64 48`). **Never prints the value.**
   - Unit tests: missing, too short, placeholder, identical secrets, valid.
3. **S4 caution — verify before you code.** `import 'server-only'` throws outside the Next
   `react-server` condition, so it may break `payload migrate` / `generate:types`, which load
   `payload.config.ts` through the Payload CLI. Test it. If it breaks, **do not drop S4**: propose
   the replacement in "Questions for CTO" (e.g. lint rule that forbids importing server modules
   from `'use client'` files + a CI grep of `.next/static` for secret variable names) and continue
   with the rest of the task.
4. **`.env.example`** with placeholders and a comment per variable. `.env` stays local.
5. **`payload.config.ts`**:
   - `postgresAdapter` with `migrationDir`, **`push: false`** (schema changes only via migrations).
   - `sharp`, `lexicalEditor()`, `typescript.outputFile`, `secret` from `env`.
   - `localization`: locales `ar` (`rtl: true`, default) and `en`, `fallback: true`.
   - Admin i18n: `ar` + `en` from `@payloadcms/translations`, Arabic as the default.
     **Verify** what Payload 3.91 does when the browser sends `Accept-Language: en-US` on a first
     visit. Acceptance needs the admin to open in Arabic and be switchable to English. If 3.91
     always prefers the browser language, document it with evidence and ask the CTO. Do not patch
     admin internals.
   - `graphQL.disable: true` (H7). `serverURL`, `cors`, `csrf` = `[SERVER_URL]` (H1).
6. **`next.config`** — `withPayload`, `output: 'standalone'`, `poweredByHeader: false`,
   `images.remotePatterns: []` for now, `headers()` with H2 **except HSTS**:
   `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: SAMEORIGIN`,
   `Permissions-Policy`, `Cross-Origin-Opener-Policy`; plus `X-Robots-Tag: noindex` on `/admin`.
7. **`robots`** (H7) — `app/robots.ts` (or static) disallowing `/admin` and `/api`.
8. Frontend: keep one minimal placeholder page with **no business content**. No CSP / `proxy.ts`
   yet (that is Phase 3, H3).

## Evidence required in the report
- `docker compose -f docker-compose.dev.yml ps` and the pinned image line (tag@sha256)
- Three boot attempts with output: no `PAYLOAD_SECRET`; a 20-char secret; valid `.env`
- `curl -sI http://localhost:3000/` and `curl -sI http://localhost:3000/admin` (full headers)
- `curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/api/graphql` (GET and POST)
- `curl -s http://localhost:3000/robots.txt`
- Result of the `server-only` vs Payload CLI check (exact command + output)
- Admin language behaviour with `Accept-Language: en-US` and `ar` (screenshots in
  `docs/reports/phase-1/`)
- `pnpm lint`, `pnpm typecheck`, `pnpm test`

## Acceptance criteria
- [ ] DB port bound to `127.0.0.1` only; image pinned by digest; no default credentials.
- [ ] App refuses to start with a clear message if `PAYLOAD_SECRET` is missing or < 48 chars,
      and the message never contains a secret value.
- [ ] `push: false`; no schema change can reach the DB without a migration.
- [ ] GraphQL returns 404 / disabled for GET and POST.
- [ ] All H2 headers (except HSTS) present on `/` and `/admin`; no `X-Powered-By`.
- [ ] `/admin` sends `X-Robots-Tag: noindex`; robots disallows `/admin` and `/api`.
- [ ] Env unit tests pass.
