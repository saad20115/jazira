"Interactive systems"

**Rewritten 2026-10-22 (supersedes the earlier procedural Three.js version).** The client wants
the photo-real tower from Figma, and choosing a system in the side list must move the view
cinematically to that system and show the related projects. `reference/3d/scene.js` is **not**
used for this section any more.

## How it works (decided)
- **Look = pre-rendered, not real-time.** Photo-real quality like the Figma render is impossible
  in real-time WebGL on phones within our budget. The tower and its MEP systems are rendered
  offline (Blender/Cycles) as one hero still + one short cinematic clip per system. The browser
  only plays video: zero GPU cost, identical on every device.
- **Interaction = HTML on top of the video.** Hotspot labels, the systems accordion and the
  related-projects panel are normal accessible HTML positioned over the frame.
- **Assets are produced separately** (task `A-1`, owner decided by the user). This task builds
  the player against a **shot manifest** and runs on placeholder clips until the real ones land.

## Scope
1. **Shot manifest** `src/components/systemsExplorer/shots.ts` (typed): `hero` still + 5 shots
   `hvac`, `fire`, `plumbing`, `power`, `smart`. Each shot: `forward` and `reverse` clip
   sources (AV1 WebM + H.264 MP4, desktop 1440 px and mobile 828 px), `endFrame` still
   (AVIF/WebP), duration, and `hotspots[]` (`id`, `x`/`y` in 0–1 of the frame, label i18n key,
   anchor side). Final assets live in `public/systems/<version>/…` with immutable names.
2. **Placeholder assets** (until A-1 delivers): generate with a script (`pnpm systems:placeholders`,
   ffmpeg via a pinned dev dependency or a documented system binary — justify) a slow push-in
   on the region of `tower-render.png` where each system would be (roof → HVAC, ground/plinth →
   fire & plumbing, podium → power, mid floors → smart). Clearly labelled "placeholder".
3. **Player** — two stacked `<video muted playsinline preload="none">` elements for seamless
   cuts; poster = `hero`. Flow: select system → play `forward` of that shot → hold on `endFrame`
   + show hotspots (staggered fade) → selecting another system plays current `reverse` then next
   `forward` (target ≤ 4 s total); "Back to overview" plays `reverse`. Rapid clicks never stack:
   the latest selection wins, in-flight playback is cut at a clean point.
4. **Loading budget** — nothing beyond the hero still (responsive AVIF/WebP, LCP-safe, exact box
   reserved) loads with the page. Clips load on **intent**: hover/focus of an accordion item
   (desktop) or tap (touch); the first shot may prefetch when the section is in view **only** if
   `saveData` is off and the connection is not 2g/3g. Each clip ≤ 2.5 MB desktop / ≤ 1.2 MB mobile.
5. **Accordion ↔ view sync** — opening an accordion item (design 105:310) selects the shot;
   the URL hash `#systems-hvac` reflects it (shareable, no scroll jump); keyboard: arrow keys move
   between systems, Esc returns to overview.
6. **Related projects panel** — for the selected system, fetch (server-side, cached by tag)
   up to 3 **published** projects whose `scope` contains any of the system's `disciplines`,
   ordered by `featured` then `order`; ProjectCards slide in (cinematic stagger, transform/
   opacity only) with "All {system} projects →" linking to `/projects?scope=<discipline>`.
   Empty state when none.
7. **Fallbacks** — `prefers-reduced-motion`: no video; crossfade hero → `endFrame` (300 ms).
   Video error / autoplay blocked: same crossfade. No JS: hero still + the accordion still works
   as content.
8. **"Open the live 3D model"** stays visible but disabled ("coming soon") until P3-T11 ships;
   no Three.js in this task.
9. RTL: hotspot anchors mirror; panel slides from the inline-end side.

## Evidence required
- Screen recording (desktop + mobile, `ar` + `en`): overview → HVAC → Fire → back, rapid
  clicking, keyboard only, reduced motion.
- Network waterfall of first load (no clip requests) and of selecting HVAC (one clip only).
- Lighthouse mobile on `/ar` with the section: Performance ≥ 90, CLS 0 from this section.
- Side-by-side of the overview state at 1440 vs `04-interactive-systems.png`.

## Acceptance criteria
- [ ] Overview state matches the Figma section within fidelity rules.
- [ ] No clip is downloaded before intent; total page weight on load unchanged except the hero.
- [ ] Rapid selection never shows a broken frame or stacked audio/video.
- [ ] Related projects come only from published CMS data, filtered by discipline.
- [ ] Fully keyboard and screen-reader operable; reduced-motion path has no video.
- [ ] Swapping placeholder → final assets is a manifest/version change only (no component code).
