# P3-T5 — 3D building section

Phase 3 · branch `phase-3-frontend` · design: 111:1608 (section), 116:1199 (12 angle frames) ·
reference: `reference/3d/scene.js` · specs: `docs/05-design.md` "3D building section"

## Scope
1. Port `reference/3d/scene.js` into `src/components/building3d/` as typed modules (no `any`);
   colours from tokens where the design uses brand colours.
2. `three` pinned exact (latest stable), plus only the addons the scene uses, imported from
   `three/examples/jsm/...` — no extra 3D wrapper library unless justified.
3. Loaded with `next/dynamic` (`ssr: false`) **only when the section enters the viewport**; not in
   the initial JS bundle (prove with the build's route chunk list).
4. Interaction: pointer + touch drag to rotate, auto-rotate when idle, pause when off-screen or tab
   hidden, dispose renderer/geometries on unmount.
5. Fallback to `home-page.building3d.fallbackImage` when: `prefers-reduced-motion`, no WebGL2,
   `navigator.hardwareConcurrency <= 4` or `deviceMemory <= 4`, or a render error.
6. Canvas has an accessible name and the section text explains it; the canvas is not a keyboard
   trap.
7. "Open the live 3D model" (label from `interactiveSystems.liveModelLabel`) opens the same scene
   in a full-screen dialog (focus trap, Esc closes, renderer disposed on close). No separate site.
8. Optional link between the Accordion and the model (e.g. highlight a floor when a system opens)
   only if it costs no extra library — say if you did it.
9. Compare the rendered model at the 12 angles with the 12 angle frames in
   `design/screenshots/components/3d-building.png`.

## Evidence required
- Build output showing the 3D chunk is separate and lazy; network waterfall proving it loads only
  on scroll.
- Screenshots at 0°, 90°, 180°, 270° next to the matching design frames.
- Lighthouse mobile on `/ar`: Performance must stay ≥ 90 with the section present.
- Recording of drag + auto-rotate; screenshot of the fallback with reduced motion.

## Acceptance criteria
- [ ] Not in the initial bundle; LCP unaffected.
- [ ] Fallback paths all work (tested by forcing each condition).
- [ ] No memory leak on route change (heap snapshot before/after 5 navigations, in report).
