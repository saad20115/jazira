## How it works (decided)
- **First paint = the photo-real hero still** (A-1 render from `CAM_hero`, same framing as
  Figma) inside the card: LCP-safe, exact box reserved, no JS needed.
- **Live 3D replaces it in place** (Three.js, GLB from A-1 with baked lighting) as soon as the
  visitor shows intent (hover/focus/tap on the card or an accordion item) — or when the section
  is in view on capable devices with a fast connection. The 3D camera starts at **exactly**
  `CAM_hero`, and the swap is a 300 ms crossfade, so it feels like the photo "comes alive".
- **Systems = camera moves in real time** in the same canvas: selecting a system in the
  accordion (or a hotspot) flies the camera to that system's viewpoint (`CAM_hvac` …, from the
  GLB), ghosts `ARCH_facade` to ~15 % opacity, lights the system in gold, shows HTML labels and the
  related-projects panel. "Exit" flies back to the overview.
- **Weak devices** (no WebGL2, low memory/cores, `saveData`, reduced motion, render error) keep
  the still and use pre-rendered end-frame stills per system (crossfade) — the same UI, no 3D.

## Scope
1. **Card states** — `overview` (still or live), `system:<id>`, `exploring` (user moved the
   camera freely). Same card size in every state; nothing opens outside the card.
2. **Controls inside the card**
   - Drag to rotate (pointer and one-finger touch **only after activation**, see 3), pinch /
     wheel to zoom, double-click/tap to zoom to the point under the cursor.
   - On-card buttons (bottom-inline-start, matching the design's "Open the live 3D model" button
     position): zoom +, zoom −, reset view, and when a system is open "Exit system".
   - Keyboard (card focused): arrows rotate, `+`/`-` zoom, `0` reset, `1`–`5` systems, `Esc` exits
     the system / deactivates.
   - Limits: min/max distance, polar-angle limits (never under the ground or above the zenith),
     no clipping through the façade except the controlled "go inside" of a system.
   - Auto-rotate slowly in `overview` when idle; stop on any input; resume after 8 s idle.
3. **No scroll hijacking** — the page must keep scrolling normally. The card is inactive until
   the visitor clicks/taps it (or focuses it with Tab); only then does the wheel zoom and a one-finger
   drag rotate. A small hint ("اسحب للتدوير · Drag to rotate") shows on first activation; clicking
   outside or `Esc` deactivates. Two-finger gestures always pass through to page zoom on mobile.
4. **"Go inside / exit" per system** — each system has a scripted camera path from A-1
   (`CAM_<system>` + optional inner waypoint). Entering animates along it (≈1.5 s, ease in/out,
   facade fades), the user can then orbit **around the system's pivot** within limits; "Exit" returns
   along the path. Switching systems goes via the overview pivot, never through geometry.
5. **Accordion sync** — opening an accordion item (105:310) = entering that system; the URL hash
   `#systems-hvac` reflects it (shareable, no scroll jump); closing = exit.
6. **Related projects panel** — up to 3 published projects whose `scope` contains the system's
   `disciplines` (server-side, cached by tag), slides in over the card's inline-end side on
   desktop / below the card on mobile; "All … projects →" links to `/projects?scope=…`.
7. **Labels** — HTML labels anchored to 3D points (`hotspots` empties in the GLB, projected every
   frame, hidden when occluded), accessible names, RTL mirrored.
8. **Loading & budgets**
   - Initial page: only the hero still (AVIF/WebP responsive). `three` and the viewer chunk load
     on intent (or in-view prefetch on capable devices); never in the initial bundle.
   - Two-stage model: `tower-lite.glb` ≤ 2.5 MB (shown first) then `tower.glb` ≤ 8 MB swapped in
     when loaded; meshopt + KTX2; baked lightmaps (no real-time shadows), one environment map.
   - Render on demand (no frames when nothing moves), DPR cap 1.5 desktop / 1.25 mobile, pause
     off-screen and when the tab is hidden, dispose on unmount; no long task > 50 ms (do heavy
     setup in idle time).
   - Lighthouse mobile on `/ar` with the section: Performance ≥ 90, CLS 0 from this section,
     TBT ≤ 200 ms.
   - **CSP (security H3a):** KTX2Loader + MeshoptDecoder need `'wasm-unsafe-eval'` and
     `worker-src 'self' blob:` on the home pages only; self-host `basis_transcoder.{js,wasm}` from the
     same `three` version (A-1 used `three@0.186.1` — pin the same, or re-verify the assets with
     yours). Evidence: response headers of `/ar` vs `/projects`, zero CSP violations after entering
     every system.
8b. **Weak GPUs — three tiers, decided at run time**
   - *Before loading:* no WebGL2, `deviceMemory < 4`, `hardwareConcurrency ≤ 4`, `saveData`,
     2g/3g, `prefers-reduced-motion` → **stills tier** (no 3D download at all).
   - *While running:* measure frame time for the first 2 s of interaction (and continuously,
     rolling 60 frames). Below ~45 fps → **low tier**: DPR 1, lite GLB only, no anti-aliasing
     pass, simpler façade transparency. Below ~24 fps in low tier → crossfade to the **stills
     tier** without losing the selected system or the user's place in the accordion.
   - `webglcontextlost` / any render error → stills tier, logged once (no PII).
   - The stills tier keeps the same card, accordion, labels (positioned from the manifest's
     per-system 2D hotspot list), related-projects panel and URL hash — only free rotation is
     missing.
   - Evidence: force each tier (query flag `?gfx=stills|low|high`, dev only) and record them; a
     run with Chrome's CPU throttling ×6 must end in low or stills tier, never a stuttering canvas.
8c. **Phones (expected to be most visitors)**
   - Layout < 768: the card is full width (square), the accordion sits **below** it, the
     related-projects panel below the accordion; labels shrink to dots that expand on tap.
   - The 3D model is **never auto-loaded on a phone**: the still shows a "استكشف بالـ 3D · Explore
     in 3D" button; only that tap downloads the viewer + lite GLB (≈ 2.5 MB). Without the tap the
     visitor still gets the stills tier experience (systems, labels, projects).
   - Phones use the **lite GLB only** (the full model is for tablets/desktops — iOS Safari kills
     tabs that use too much GPU memory), DPR ≤ 1.25, 30 fps cap, render on demand.
   - Touch: while active, one finger rotates and pinch zooms **inside the card**; a visible "تم ·
     Done" button (and tapping outside) deactivates so one-finger scrolling returns to the page.
     Never trap the page scroll.
   - Respect iOS Low Power Mode / thermal throttling: the run-time FPS check (8b) drops to low or
     stills automatically.
   - Evidence: real devices or emulation for iPhone (Safari) and a mid-range Android (Chrome):
     recordings of tap-to-explore → HVAC → exit → Done → page scroll; memory peak on iOS.
9. **Placeholders until A-1 delivers** — build against `public/systems/<version>/manifest.json`

   R1 blockout GLB from A-1 as soon as it exists; before that, a simple box tower generated in
