# P2-T2 — `videos`, `brands`, `stats`, `materials`

Phase 2 · branch `phase-2-content` · specs: `docs/02-content-model.md` (original sections **and**
the 2026-10-21 Addendum, which wins on conflicts) · security: Z1, I5

## Scope
1. `videos` (group Media) — `mimeTypes` mp4/webm only, max 100 MB enforced **per collection**
   (the global upload limit stays 10 MB for images — explain how you did it), magic-byte check as
   in `media`, `title` (L, required), `poster` (→ media). Access as `media`.
2. `brands` (group Company) — `name` (unique), `logo` (→ media, optional), `origin` (L),
   `website` (URL, http(s) only), `showInMarquee`, `order`.
3. `stats` (group Company) — per Addendum.
4. `materials` (group Company) — `itemNo` (unique), `system` select, `description` (L),
   `brands` (→ brands, hasMany, required), `notes` (L); default sort `itemNo`; admin list columns
   itemNo, description, system, brands; filter by system.
5. Every collection: `timestamps`, explicit `access` (Z1), `useAsTitle`, `defaultColumns`, Arabic +
   English `labels`, `admin.group`, `admin.description` in Arabic and English that tells a
   non-technical editor what this is for. Revalidate hooks from P2-T1 wired.
6. Migration for these collections.

## Evidence required
- `pnpm test`: access tests (anonymous read OK where public, writes 403; editor CRUD OK);
  upload tests for `videos` (mp4 OK, 101 MB rejected, `.mp4` that is really HTML rejected).
- Admin screenshots (Arabic UI) of each list and edit view.
- lint, typecheck, migration file listed.

## Acceptance criteria
- [ ] Fields, access and admin config exactly as specified.
- [ ] Video size/type limits enforced server-side (tested).
- [ ] Deleting a brand that materials use is blocked with a clear Arabic/English message (or
      explain the chosen behaviour).
