# P6-T1 — Production packaging (built and tested locally only)

Phase 6 · branch `phase-6-deploy` · specs: `docs/01-architecture.md` §4 · security: R1–R3,
R5, R6, H2, H5, H6, A7, D1

**Do not connect to any server. Do not touch Odoo.** Everything here runs on this machine.

## Scope
1. `Dockerfile` — multi-stage, `node:24-*-slim` pinned by digest, `pnpm install --frozen-lockfile`,
   Next `standalone` output, non-root UID, only runtime files in the final image, healthcheck
   endpoint (`/api/health` — DB ping, no details leaked).
2. `docker-compose.prod.yml` — `web` + `db` (Postgres 18 by digest) on an internal network; DB not
   published; `web` bound to `127.0.0.1:3000`; `read_only: true` + tmpfs `/tmp` + `media` volume;
   `no-new-privileges`, `cap_drop: [ALL]`, memory/CPU limits sized for a VPS shared with Odoo
   (state your numbers); app DB user owns only the app DB (D1); migrations run as a one-off
   command, not on every boot.
3. `deploy/nginx/aljazira.conf` — TLS 1.2/1.3, HTTP→HTTPS 301, H2 headers incl. HSTS, H6 rate
   limits and body sizes, `/admin` + `/api/users/*` restriction placeholder for A7 (both options
   written, commented), gzip/brotli, caching for `/_next/static`. Validate with `nginx -t` in a
   container.
4. `deploy/backup/` — nightly `pg_dump` + media tar, retention 14 daily / 8 weekly, encryption
   before off-server copy (D3), and a **restore script**. Prove backup → restore into a scratch DB
   locally.
5. Log rotation and an uptime-check recommendation (R6).
5b. **sharp in standalone** (from the P1-T2 review, R-6): make sure the `sharp` native binary
   and libvips (`@img/sharp-linux-x64`, `@img/sharp-libvips-linux-x64` or the arm64 pair) are in
   the final image (e.g. `outputFileTracingIncludes` or installing them in the runner stage).
   Prove it: upload a JPEG through the admin inside the production container and show the four
   generated WebP sizes.
5c. **Standalone boot + single job runner** (from the P2-T4 review, R-14/F6): the production
   entry is `node server.js` in the Linux image, not `next start`. Prove that `instrumentation.ts`
   (env check + `getPayload({ cron: true })`) loads there, that scheduled publish runs in that
   container, and that exactly **one** process runs jobs (`PAYLOAD_JOBS_AUTORUN` explicit, any
   second replica/worker off). Boot fails fast with a clear log line if Payload/DB/sharp init fails.
6. Draft `docs/runbook-deploy.md`: prerequisites (from P6-T2), step-by-step deploy beside Odoo,
   rollback to the previous image tag, how to verify Odoo is untouched.

## Evidence required
- `docker build` output + image size; `docker compose -f docker-compose.prod.yml up` locally with
  the site working at `127.0.0.1:3000`.
- `docker inspect` showing non-root user, read-only root FS, dropped caps, limits.
- Write attempt to `/app` inside the container fails (proof of read-only FS).
- `nginx -t` OK; backup + restore transcript; rollback rehearsal (two image tags).
