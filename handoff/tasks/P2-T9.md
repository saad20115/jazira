# P2-T9 — Login enumeration hardening (timing + locked message)

Phase 2 · branch `phase-2-content` · security: A1, A5 (spirit), H6 · found in the P2-T6 round 4 review

## Problem (measured on a production build)
- **Timing oracle:** `POST /api/users/login` answers an unknown email in ~7 ms (median) and a
  wrong password for an existing user in ~303 ms — the password hash runs only for existing users.
  One request is enough to tell whether a staff email exists.
- **Message oracle:** a locked account returns "تمّ قفل هذا المستخدم…" while an unknown email gets
  the generic message, so anyone can confirm an email (and lock that person out) with 5 bad tries.

## Scope
1. Unknown-email logins take the same time as wrong-password logins: run a dummy hash with the
   same algorithm and cost Payload uses (read it from the installed `payload` version, do not
   guess), via the smallest supported hook/override — no patching of `node_modules`. If Payload
   offers no clean hook, write a thin custom login endpoint that delegates to `payload.login` and
   say exactly why.
2. Locked accounts answer with the **same status and body** as a wrong password (the lockout still
   applies; staff learn about it from the admin unlock flow). Keep A1 behaviour: the 5th failure
   locks, 15 min.
3. Do not weaken anything else: `forgot-password` stays non-enumerating, cookies/flags unchanged.
4. Note for P6: Nginx `login` rate limit (H6) is still required; this task does not replace it.

## Evidence required
- A timing script against `next start`: 20 samples each for unknown email / existing email + wrong
  password / locked account — medians and spread in a log; the difference must be within noise
  (state your threshold, e.g. < 15 % of the median).
- Tests: identical status + body for unknown / wrong password / locked; lockout still happens on
  the 5th failure; correct password after the lock window works.

## Acceptance criteria
- [ ] No timing or message difference that reveals whether an email exists.
- [ ] A1 lockout unchanged; all earlier auth tests green.
