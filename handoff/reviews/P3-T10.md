### Findings
- **P10-1 [major] A CSP violation on the contact page.** `/en/contact` and `/ar/contact` raise an enforced
  `securitypolicyviolation` (`script-src`, blocked `eval`) from a client chunk: Zod v4's `allowsEval` probe
  (`Function("")` in try/catch). It writes nothing to the console, so the P3-T10 spec, which only reads console text,
  cannot see it. Acceptance "zero CSP violations on every page" is not met. **Fixed looks like:** no eval probe in the
  client bundle (for example Zod's `jitless` config where the schema runs in the browser), and a
  `securitypolicyviolation` listener in the a11y spec with a must-fail.
- **P10-2 [major] After the full e2e suite, a published service page stays 404.** On the test DB after the e2e run,
  `/en/services/general-contracting` answered 404 while the document's latest version is `published` (ar: 200), and it
  still answered 404 after a server restart and a rebuild. The sitemap lists the URL. Every later run of the P3-T10 spec
  on that DB fails at this page. The P3-T6 spec unpublishes and republishes this service and does not check the restore.
  A clean unpublish → republish of the same service (P5 build, fresh DB) followed the CMS within 2 s, so the trigger is
  in the e2e sequence; I did not isolate it (a repeat check is in the P2-T7 review). **Fixed looks like:** the cause
  found; the P3-T6 restore asserted; the suite can run twice on one DB.
- **P10-3 [blocker, inherited from R-1] R1-6 is present here.** Editing only the alt text of an image or the title of a
  video in the dashboard is refused (400) for admin and editor on this build. Fixed through R-1.
- **P10-4 [minor] Page titles repeat the company name** when the CMS SEO title is empty: "Our Services | Al Jazira for
  Imdad Smart Co. | Al Jazira for Imdad Smart Co." (`/en/services`, `/en/projects`, project detail; the same in `ar`).
- **P10-5 [minor] The hard-coded text scan misses constants** (M-241 item 3, confirmed with a fixture). Acceptable as
