### CTO decision — intro, round 4 (replaces the R-15 wording)
My R-15 wording ("≤ 1.6 s from navigationStart") turned a slow first paint into a timing problem.
The spec (`docs/05-design.md` "CTO decisions" §3) is now read as follows:
1. **Pure CSS.** The inline script only decides `seen` or `active` and sets `data-intro`. One CSS
   keyframe timeline does the rest on the SSR overlay: the logo reveal, then the fade-out, ending in
   `visibility:hidden; pointer-events:none` with `animation-fill-mode: forwards`.
   - React does no timing. It handles only Skip, Esc and click, and removes `inert` on `animationend`.
2. **Duration:** **≤ 1.6 s from the overlay's first visible frame**, on every viewport and device. The
   logo is fully visible for **≥ 300 ms**.
3. **No branches** on viewport, timing, connection, user agent or automation.
4. **No overlay after 2.5 s from navigationStart, whatever happens.** This is a CSS
   `animation-delay` / `@keyframes` cap computed by the inline script from `performance.now()`, not a
   `setTimeout`. If the first paint comes later than about 1.2 s, the inline script sets `seen` and
   the intro is skipped for that visit. **This is the only allowed skip.** It is the same rule on every
   device, and it must be reported with the numbers.
5. **Proof:** your rAF timeline at 412 / 768 / 1440, each throttled and unthrottled, in `ar` and
   `en`, 3 runs each. Report **all** runs: first visible, logo fully visible, hidden, and frame count.
   Add a webm for each width.
