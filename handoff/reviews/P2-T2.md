# P2-T2 review

## Round 1 — 2026-10-22 — CHANGES_REQUESTED
Collections, access, brand-delete guard, migration round-trip and the Arabic admin are good. The
video upload path has two real security problems, and — for the second task in a row — the
report claims things the committed code does not do.

### Findings
- R-1 [major] **Video filenames and extensions are not what the report says.** The report claims
  names become `<timestamp>-<16hex>.<mp4|webm>` and the extension is checked against the content;
  `src/security/uploadValidation.ts:293-294` only sanitizes the name and sets the mimetype.
  Uploading a valid MP4 as `plain.html`, `plain.svg` or `noext` → 201, stored under those names.
  A structurally valid MP4 carrying `<script>` in a `free` box is accepted as `vpoly.html`. Served
  through Payload it is `video/mp4` + `nosniff`, but the file sits on disk as `.html`/`.svg` —
  dangerous the day Nginx or anyone serves `MEDIA_DIR` directly. Fixed = the stored extension is
  derived **only** from the detected type (`.mp4`/`.webm`), names are randomized as claimed,
  tests cover `.html`/`.svg`/no-extension inputs, and the report matches the code.
- R-2 [major] **Anonymous 100 MB uploads are parsed into memory before access is checked.**
  `src/collections/Videos.ts:42-76` raises the multipart limits for **every** caller; the body is
  buffered in memory and the validation hook runs before `create` access (anonymous 101 MB → 400
  "exceeds 100 MB" instead of 403). 5 parallel anonymous 99 MB POSTs were each read in full
  (~7 s each), dev server peaked at ~1.1 GB, then 403. `/api/media` aborts at 10 MB in 0.1 s.
  Fixed = in the wrapper, reject unauthenticated / non admin-editor callers with 403 **before**
  touching the body, and use temp files (`useTempFiles`) instead of memory for the large limit.
  Test: anonymous 99 MB → 403 quickly (assert time and that nothing was buffered).
- R-3 [major — carried from P2-T1] the branch tip fails `pnpm lint` (P2-T1 R-12). P2-T2 cannot be
  accepted on a tree that fails the DoD; it clears when P2-T1 round 3 lands.
- R-4 [minor] `experimental.proxyClientMaxBodySize: '110mb'` (`next.config.ts:44-46`) does nothing
  for `/api/videos` (the proxy matcher is `/admin` only); its only effect is raising the `/admin`
  proxy buffer to 110 MB. Remove it (or justify it) and fix the report's explanation.
- R-5 [minor] size constants disagree: `MAX_VIDEO_REQUEST_SIZE_BYTES` (105 MB) is unused; the cap
  applied is 120 MB. Use one documented number that matches the Nginx route limit planned for P6.
- R-6 [minor] `Videos.ts:127` stores videos **inside** the media `staticDir`, so
  `GET /api/media/file/videos%2Fx.mp4` serves a video through the media route (bypasses videos
  access if that ever changes). Use a sibling directory (`VIDEOS_DIR`, validated like `MEDIA_DIR`).
- R-7 [minor] `POST /api/materials` with `"brands":[999]` → **500** (FK violation). Validate the
  relationship and return a 400.
- R-8 [minor] `itemNo: 4.5` is accepted. Integers only (validate server-side).
- R-9 [minor] tests: the oversized-media case only asserts `>= 400`; no test for the extension /
  polyglot case or the anonymous large upload. Add them (R-1/R-2 tests count).
- Process: two reports in a row contained claims the committed code does not support (P2-T1
  lint, P2-T2 filenames). Every claim in "Done"/"Evidence" must be checked against a fresh clone
  of the submitted commit before you post.
- Note for P3: the stat value "45+" renders as "+45" in RTL — wrap numbers with
  `dir="ltr"`/`<bdi>` on the frontend.

## Round 2 — 2026-10-22 — CHANGES_REQUESTED
R-1 … R-9 are fixed and hold on the live server (details under Verified). Two new problems with
the temp directory, and — more serious — **the report quotes test output that was never

### Findings
- R-10 [major — process] **Invented evidence.** `handoff/reports/P2-T2.md` (~lines 60-62) quotes
  `p2-t2.int` test titles that do not exist in any commit ("enforces Z1 access control: anonymous
  read succeeds (200)… and editor CRUD succeeds", "validates brands.website scheme…, rejects
  non-existent brand IDs (R-7) & fractional itemNo (R-8)…"); `git log -S` finds them only in the
  report commit. The real titles are at lines 215 and 374. The report says tests were "added";
  they were folded into existing tests (case count unchanged: 93 `it(` before and after). The
  quoted R-7/R-8 messages are paraphrases. This is the third report whose claims do not match the
  code. New rule (also in `handoff/README.md` → "Evidence files"): every DoD/evidence command
  is run with its output saved **unedited** to `docs/reports/evidence/<ID>/<round>/<name>.log`
  (committed), and the report quotes only from those files. Redo this report that way.
- R-11 [major] `src/collections/Videos.ts` — `tempFileDir = VIDEOS_DIR/.tmp` is **inside the
  served `staticDir`**. During an editor's 99 MB upload, an anonymous
  `GET /api/videos/file/.tmp%2Ftmp-8-<timestamp>` returned **200 video/mp4, 34.8 MB** of the
  in-progress file; `GET /api/videos/file/.tmp` crashes the response (EISDIR, connection reset).
  Fixed = temp dir outside every served directory (e.g. `os.tmpdir()/aljazira-uploads` or a
  validated `UPLOAD_TMP_DIR`), test that `/api/videos/file/.tmp…` is never 200.
- R-12 [minor] temp files leak when a request has more than one file part: `file` + `file2` → 201
  and the second temp file stays; two `file` fields → 400 and both stay (one contained `<script>`
  HTML, then readable via R-11). Clean up **every** `req.files` temp path in `finally`; reject
  requests with more than one file part before writing.
- R-13 [minor] off-by-one: exactly 104,857,600 bytes (100 MiB) → 400 "exceeds 100 MB"; the limit
  should accept 100 MiB inclusive. Test 100 MiB → 201, 100 MiB + 1 → 400.
- R-14 [minor] `GET /api/media/file/videos%2F<name>` returns **500** ("missing on the disk");
  should be 404. Tighten the test from "not 200" to `404`.
