### Findings
- **R1-1 [blocker] The e2e suite cannot run.**
  - `tests/e2e/global-setup.test.ts` is a Vitest file inside Playwright's `testDir`.
  - Playwright's default `testMatch` collects it, and it fails at load with
    `TypeError: Cannot read properties of undefined (reading 'config')` at `global-setup.test.ts:7`.
  - So `pnpm exec playwright test` aborts before any test runs (`e2e-default.log`, exit 1 after 5 s).
  - **Fixed looks like:** move this unit test out of `tests/e2e/` (for example to `tests/unit/` or next to a helper
    that you move out of `tests/e2e/`). Do not change `playwright.config.ts`, which is CTO-owned. The unfiltered
    `playwright test` must run.
  - The verifier's diagnostic run with a path filter (`'spec\.ts$'`): 15 passed and 1 failed. The failure is the
    known, inherited P3-T2 R-9 drawer test, which also fails on the other branches.
- **R1-2 [major] The e2e target guard checks a variable, not the database the server uses.**
  - `assertSafeE2ETarget` (`tests/e2e/global-setup.ts`) resolves
    `E2E_DATABASE_URL || TEST_DATABASE_URL || DATABASE_URL`.
  - With the standard `.env`, `TEST_DATABASE_URL` ends in `_test`, so the guard passes whatever the server under test
    is connected to.
  - **Shown in this run:** the e2e ran against the 3329 server, whose `DATABASE_URL` is the dev database
    `aljazira_verify`, not `_test`. The guard let `first-register` and the global writes through.
  - This is the case A-03 exists for: "never `first-register` outside a fresh test DB".
  - **Fixed looks like:** the guard checks the database the server under test was started with, and refuses
    otherwise. For example, require `E2E_DATABASE_URL`, with no fallback, to equal the `DATABASE_URL` the server is
    started with, and make the e2e start its own server on a `_test`/`_e2e`/per-run database. Add a must-fail: a
    server on a non-test database is refused.
- **R1-3 [minor] The setup still tries the password on other accounts.** `ensureE2EAdminToken` tries
  `E2E_ADMIN_PASSWORD` against `admin@aljazira.local` and `p3-t12-evidence-admin@aljazira.co` too. **Fixed looks
  like:** only the e2e admin's email (or `E2E_ADMIN_EMAIL`).
- **R1-4 [minor] `scripts/record/p3-t14-motion-recordings.mjs` calls `first-register` with no target guard.** It
  takes its password from env and restores `arabicEnabled`, which is good, but it runs against any `BASE_URL`. This
  path is executor-owned. **Fixed looks like:** the same loopback and test-database guard as the e2e setup.
- **R1-5 [minor] The entropy floor is below the card's 32 random bytes.**
  - `hasSufficientSecretEntropy` needs 48 characters and an estimated ≥ 3.5 bits per character. That is about 168
    bits, less than the 256 bits that 32 random bytes give.
  - **Fixed looks like:** a floor of at least 256 estimated bits (length × bits per character), with the unit test
    moved to match.
  - The superuser check matches role names only (`FORBIDDEN_SUPERUSER_DB_ROLES`). That is accepted for now; P6-T1
    creates the production role.
