  - "All 6 versioned page globals" for Z2: the tests cover only 3. Either test all 6 or say 3.
  - The seoPlugin is said to be "wired on services and projects", but it has `collections: []` and
    meta comes from `seoGroupField`.
- **R-6 [major, security — must be fixed before any P3 data code] The Z6 lint rule can be evaded.**
  - These slip through:
    - an aliased receiver, or a receiver named `client`;
    - a destructured `find`;
    - `payload['find']` and `.call()`;
    - `{overrideAccess:false, ...{overrideAccess:true}}`;
    - `findVersionByID` and `countVersions`;
    - an undocumented second justification comment form.
  - A name heuristic will never be complete. **Required design (CTO decision):**
    1. In `src/app/(frontend)/**` and `src/components/**`, importing `payload`, `@payload-config`
       or `getPayload` is a lint error. Use `no-restricted-imports` or your custom rule; it is an
       import check, not a name heuristic. Public data comes only from `src/lib/cms/*`.
    2. `src/lib/cms/*` calls Payload through **one typed wrapper** (e.g. `cmsFind`, `cmsFindByID`,
       `cmsFindGlobal`, `cmsCount`). The wrapper sets `overrideAccess: false` itself, and its
       options type has no `overrideAccess` key, so a caller cannot pass one. `draft` is allowed
       only from `draftMode()`.
    3. Keep the existing rule as a second layer. Add the missing methods, accept only the one
       documented justification form, and add tests for the evasions above.
  - P3-T1's data layer must use this wrapper. Rebase P3-T1 accordingly.
