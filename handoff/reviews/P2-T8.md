### Findings
- **R-11 [major, security] Z6 layer 2: the wrapper passes through any key it does not explicitly
  delete.**
  - `buildSafeCmsQueryArgs` (`client.ts:145`) removes only `overrideAccess` and `draft`.
  - A non-literal options object escapes TypeScript's excess-property check.
  - Runtime proof:
    - `cmsFind({collection:'users'})` → Forbidden;
    - the same call with a smuggled `user: admin` → **all users with emails**;
    - `cmsCount` behaves the same way.
  - **Fix:** build the Payload args from an **explicit whitelist**: `collection`/`slug`, `id`,
    `locale`, `fallbackLocale`, `where`, `limit`, `page`, `sort`, `depth`, `pagination`, `select`.
  - **Tests:** injected `user`, `req`, `showHiddenFields`, `overrideAccess` and `draft` all have no
    effect.
- **R-12 [major, security] Z6 layer 1 can be bypassed through re-exports, and the report claims the
  opposite.**
  - The report says the rule bans `ExportNamedDeclaration` and `ExportAllDeclaration`. The rule has
    no export handling at all.
  - Proven end to end:
    - `src/lib/cms/reexport.ts` re-exports `getPayload` and `@payload-config`;
    - a frontend page imports them through a barrel, then calls `cms.find(opts)`;
    - result: 0 lint errors, a clean typecheck, and `overrideAccess` defaults to true on a
      public page.
  - `.js` files are not linted at all.
  - **Fix:**
    - Import **and re-export** of `payload`, `payload/*`, `@payload-config` and `@/payload.config`
      is an error **repo-wide**, except for an explicit allow-list of server modules
      (`src/payload.config.ts`, `src/lib/cms/client.ts`, collections/globals/hooks/access,
      scripts, tests, the `(payload)` admin route group). Use `no-restricted-imports` with
      overrides; it is an import rule, not a heuristic.
    - Lint `.js`/`.jsx`/`.mjs` too.
    - Add `@/lib/cms/*` to `no-server-in-client`.
    - Add the `CMS_CLIENT` sentinel to `FORBIDDEN_CLIENT_BUNDLE_SENTINELS`.
- **R-13 [major, evidence integrity] `citations.log` uses catch-all patterns that hid 11 wrong
  citations.**
  - 37 of 272 blocks use non-identifier patterns, which make up 2,171 of 3,164 lines:
    - an **empty pattern** `''` that dumps a whole file;
    - `'}'`, `'})'`, `'try {'`, `'result'`, `'name'`, `'user'`, `'req,'`, and others.
  - Behind them, 11 wrong citations:
    - `client.ts:168/185/206/223/150/132` (real lines 163/180/201/218/145/127);
    - `globals.test.ts:40/212` (blank lines);
    - `Stats.ts:37` (`req,` — a regression of a correct round-1 citation);
    - `QuoteStatusPillCell.tsx:71`;
    - `QuoteRequests.ts:546`.
  - Also wrong:
    - `require-override-access-false.mjs:411` is the `require()` check, not `.call`/`.apply`;
    - `src/components/admin/*.tsx:1` points at `'use client'`.
  - This defeats the rule's purpose, and I treat it as such.
  - **Fix:** this round adds a **mechanical citation checker** (see the README rule below).
- **R-14 [major, evidence integrity] An accepted evidence file was rewritten.**
  - `573512c` changed `docs/reports/evidence/P2-T6/r5/citations.log` (1,639 lines), which was part
    of an **accepted** round.
  - **Restore it from `2570d8d`.** Evidence of a reviewed round is immutable: corrections go in a
    new round folder.
