### Findings
- **R-10 [major] (R-4 not fixed) The DB lookups in `src/hooks/revalidate.ts` are dead code.**
  - **Cause.** `getDbAdapter(req)?.findOne` is called unbound (≈ lines 174 and 258). The drizzle
    adapter uses `this.payload`, so every call throws "Cannot read properties of undefined (reading
    'payload')". The empty `catch {}` swallows it, and the decision falls back to
    `previousDoc._status`, which is the round-1 bug.
  - **Live results:**
    - **Unpublish after a draft edit → 0 tags.** This is exactly what the admin "Unpublish" button
      sends, so the unpublished project stays on the list, detail and home pages. This is a new
      regression.
    - Local API: the first `update({ draft: true, autosave: true })` after a publish → 12 tags, and
      on a featured project → 15 tags including `/ar` and `/en`.
  - The unit tests pass only because they mock `findOne` as a free function.
  - **Fix:**
    - Read the main (published) row through a supported API, e.g. `req.payload.findByID({
      collection, id, draft: false, depth: 0, overrideAccess: true, req })`, or the adapter
      **as a method call**.
    - Never use an empty `catch`: log once and fall back to *invalidating* (fail safe), not to
      skipping.
  - **Tests:** integration tests, no DB mocks, for both:
    - unpublish after a draft edit, via REST/admin (`PATCH {_status:'draft'}`);
    - the first Local API draft/autosave right after a publish (featured and not featured).
- **R-11 [major] (R-7 not fixed) The rich-text media guard only scans the first 100 docs.**
  - `findRichTextBodyReferencingLabels` (`Media.ts:123-162`) runs `payload.find({ limit: 100 })`
    with no `where`, then scans the bodies in JS.
  - Live: with 152 projects, media used only in project #152's body deleted with 200, leaving
    `value: 14` in the body. Each delete also loads up to 800 full documents.
  - **Fix (the round-1 preferred option, now required):**
    - In `beforeChange` (drafts too), extract every upload node's ID from `body` (all locales,
      nested lists/quotes) into a hidden `bodyMedia` relationship field (`hasMany`, `media`,

      `value: 999999` is accepted.
    - The guard then queries `bodyMedia` with a `where` (main and versions, bounded).
  - Same for `services.body`. Add a migration.
  - **Tests:** a reference in doc #101+, nested nodes, the `en`-only body, and the missing-ID
    reject.
