     - Normalizes the candidate email (`email.trim().toLowerCase()`) and queries `req.payload.db.findOne` (`src/security/loginEnumeration.ts:125`) on `users`.
     - If the email does not exist (`!existingUser`) OR the user is currently locked via `isUserCurrentlyLocked` (`src/security/loginEnumeration.ts:39`) called at `isUserCurrentlyLocked` (`src/security/loginEnumeration.ts:138`), awaits `runDummyPayloadPasswordHash` (`src/security/loginEnumeration.ts:139`) with the submitted password and throws `createGenericAuthenticationError` (`src/security/loginEnumeration.ts:87`) at `createGenericAuthenticationError` (`src/security/loginEnumeration.ts:140`), which returns HTTP `401` with Payload's generic localized `errors:emailOrPasswordIncorrect` message (`"البريد الإلكتروني أو كلمة المرور المقدمة غير صحيحة."` in `ar`, `"The email or password provided is incorrect."` in `en`).
     - If the user exists and is unlocked, returns `args` unchanged so Payload's native `loginOperation` runs its real PBKDF2-SHA256 verification and `A1` `loginAttempts` / `lockUntil` counter configured via `maxLoginAttempts` (`src/collections/Users.ts:286`) and `lockTime` (`src/collections/Users.ts:287`).
   - Implemented defense-in-depth `maskLockedAuthAfterError` (`src/security/loginEnumeration.ts:152`), wired into `afterError` (`src/collections/Users.ts:363`), so if `LockedAuth` ever reaches `afterError` (e.g. a concurrent race on the 5th attempt), its response body and status are replaced with `createGenericAuthenticationError` (`src/security/loginEnumeration.ts:158`).
