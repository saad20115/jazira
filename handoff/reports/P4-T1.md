## Architectural Note on `SEED_ADMIN_USER` (`R-7`)

`SEED_ADMIN_USER` (`src/seed/materials.ts:141`) is an **in-memory synthetic `User` context** (`{ id: 0, collection: 'users', email: 'seed-runner@aljazira.co', name: 'Seed Runner (Admin)', role: 'admin', ... }`), **not** a database row in the PostgreSQL `users` table:
- Neither `brands` nor `materials` has a foreign-key column referencing `users`.
- Passing `user: SEED_ADMIN_USER` alongside `overrideAccess: false` on every `payload.count`, `payload.find`, `payload.create`, `payload.update`, and `payload.delete` call in `seedMaterialsAndBrands` (`src/seed/materials.ts:1130`) forces Payload to evaluate the collections' configured `isAdminOrEditor` access-control functions (`src/collections/Brands.ts`, `src/collections/Materials.ts`) without inserting a dummy admin user row into `users`.
