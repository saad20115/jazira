### 1.2 `src/components/IntroSplash.tsx` (`R-36`, `R-37`, `R-40`, `R-29`, `R-34`)
- Lowered `INTRO_MAX_FIRST_PAINT_MS` to the Round 2 threshold specified in `handoff/reviews/P3-T13.md` so the overlay timeline finishes with headroom before the hard cap.
- Rewrote `INTRO_PREPAINT_INLINE_SCRIPT` to follow the CTO Round 2 design:
  - Runs synchronously right after `<IntroSplash>` in `<body>`, checks the home pathname and presence of `[data-component="intro-splash"]:not([data-intro-forced="true"])`, sets `data-intro="active"` and `--intro-delay: 0ms` provisionally before `<header>` or `<main>` is parsed, and registers a single `window.requestAnimationFrame` callback.
  - Removed the `DOMContentLoaded` decision fallback (`R-37`).
  - Added a `DOMContentLoaded` listener that re-applies `inert` (`setInert(true)`) to the page landmarks (`header`, `main`, `footer`, `[data-sticky-cta="true"]`, `body > a[href="#main-content"]`) when `data-intro="active"` is still set once those landmarks finish parsing (`R-29`, `R-37`).
  - Inside the single `requestAnimationFrame` callback, reads `performance.now()` at callback execution time (`R-36`) rather than the stale `rafTs` callback parameter:
    - When `performance.now()` exceeds `INTRO_MAX_FIRST_PAINT_MS`: sets `data-intro="seen"` and clears `inert` (`setInert(false)`) before that frame paints so the overlay never paints (`R-36`, `R-37`).
    - When `performance.now()` is within `INTRO_MAX_FIRST_PAINT_MS`: keeps `data-intro="active"`, resets `ov.getAnimations({ subtree: true })` `currentTime = 0` so the CSS keyframe timeline starts from the beginning on that frame, applies `setInert(true)`, focuses `[data-intro-skip="true"]`, and attaches `animationend`, `click`, and `Escape` teardown listeners.
  - Writes `aljazira_intro_seen = '1'` only inside the `requestAnimationFrame` callback (`R-34`, `R-36`).
- Fixed the stale JSDoc comments on `INTRO_PREPAINT_INLINE_SCRIPT` and `IntroSplash` (`R-40`) so they accurately describe the `@keyframes` reveal stop and the Round 2 threshold and placement.
- Re-analyzed the Round 1 `ServicesCarousel` prop trim (`R-40`): trimming `body` and `materials` in `src/app/(frontend)/[locale]/page.tsx` did not change the rendered HTML stream because `ServicesCarousel` never rendered those properties; in Round 1 the decision appeared to pass only because `<head>` `rAF` passed a stale `rafTs` timestamp captured before main-thread HTML parsing finished. ## 2. Claims Without Numbers

- On the home route (`/en`, `/ar`), `<IntroSplash>` is the first element in `<body>` and is immediately followed by the synchronous nonce-bearing inline script before `<a href="#main-content">` and `<header>`.
- The synchronous inline script sets `data-intro="active"` provisionally before subsequent `<body>` landmarks are parsed, and registers a single `requestAnimationFrame` callback with no `DOMContentLoaded` decision fallback.
- Inside the `requestAnimationFrame` callback, the play-vs-skip decision reads `performance.now()` at callback execution time against `INTRO_MAX_FIRST_PAINT_MS`:
  - When within threshold, the overlay stays active, its CSS keyframe animations are anchored to the start of the timeline on that frame, landmarks are marked `inert` (and re-marked on `DOMContentLoaded` if still parsing), and teardown occurs on `animationend`, click, or `Escape`.
  - When above threshold, `data-intro="seen"` is set and `inert` is cleared inside the `requestAnimationFrame` callback before paint so the overlay never paints.
- `sessionStorage.setItem('aljazira_intro_seen', '1')` is written only on the home route when `[data-component="intro-splash"]` is present and only inside the `requestAnimationFrame` callback.
- Returning visits (`aljazira_intro_seen === '1'`), reduced-motion users (`prefers-reduced-motion: reduce`), and non-JS / blocked-script renders leave content visible without hiding `body`, `html`, `main`, `header`, or `footer`.
