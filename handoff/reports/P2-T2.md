# P2-T2 report — round 2

## Review findings (Round 1)
- **R-1 [major] (`src/security/uploadValidation.ts`, `src/security/uploadValidation.test.ts`, `tests/int/p2-t2.int.test.ts` — `460e354`)**:
  - **Root cause**: `validateAndSanitizeVideoFile()` validated the magic bytes and `file.mimetype` but left `file.name` untouched, so a valid MP4 uploaded as `clip.html`, `clip.svg`, `vpoly.html` (MP4 with `<script>` in a `free` box), or `noext` was stored with its attacker-supplied filename/extension.
  - **Fix**: Added `generateRandomizedVideoFilename(detectedMime)` deriving the stored extension **strictly from `detectedMime`** (`'video/mp4' → 'mp4'`, `'video/webm' → 'webm'`), ignoring the incoming filename/extension, and setting `file.name = '<timestamp>-<16hex>.<mp4|webm>'`.
  - **Tests**: Added unit assertions in `src/security/uploadValidation.test.ts` and integration tests in `tests/int/p2-t2.int.test.ts` uploading a valid MP4 as `clip.html`, `clip.svg`, `vpoly.html` (structurally valid MP4 containing `<script>alert(1)</script>` inside a `free` box with `Content-Type: text/html`), and `noext`, asserting that every stored filename matches `^\d+-[0-9a-f]{16}\.mp4$` and the file is served with `Content-Type: video/mp4`.
- **R-2 [major] (`src/collections/Videos.ts`, `tests/int/p2-t2.int.test.ts` — `460e354`)**:
  - **Root cause**: `createVideoUploadEndpoint` passed the request straight into Payload's `defaultEndpoint.handler(req)` (`addDataAndFileToRequest` → `processMultipart`), which buffered the entire 100 MB multipart body in memory before `createOperation`/`updateOperation` checked `isAdminOrEditor`.
  - **Fix**:
    1. Added `if (!isAdminOrEditor({ req })) { throw new Forbidden(req.t) }` at the very top of `createVideoUploadEndpoint` **before** `defaultEndpoint.handler(req)` is called, so anonymous requests are rejected with `403` before a single byte of the body stream is read.
    2. Configured `useTempFiles: true` and `tempFileDir: path.join(env.VIDEOS_DIR, '.tmp')` on the scoped `videos` upload config so authorized 100 MB video uploads stream to disk via Busboy temp files instead of holding 100 MB `Buffer` chunks in Node heap, with `try / finally` cleanup of `tempFilePath` on `req.file` after the operation completes or fails.
  - **Tests**: Added an integration test in `tests/int/p2-t2.int.test.ts` passing a 99 MB `ReadableStream` (`highWaterMark: 0`) to `POST /api/videos` as an anonymous user, asserting `status === 403`, `req.bodyUsed === false`, `bytesReadFromAnonStream === 0`, and `elapsedAnonLargeMs < 500`.
- **R-3 [major] (`src/fields/slug.ts` — `a1a5743`)**:
  - **Fix**: All 5 `@typescript-eslint/no-unnecessary-type-assertion` lint errors in `src/fields/slug.ts` were removed in `a1a5743` (`P2-T1` round 3). Verified below on a fresh `git clone` of `460e354` (`D:\jazira-dod-p2t2`) where `pnpm lint` exits `0`.
- **R-4 [minor] (`next.config.ts`, report correction — `460e354`)**:
  - **Fix**: Removed `experimental.proxyClientMaxBodySize: '110mb'` from `next.config.ts` and corrected the Round 1 report note below (`src/proxy.ts` matcher excludes `/api/*`, so `proxyClientMaxBodySize` has no effect on `/api/videos` and would only loosen buffering on matched routes).
- **R-5 [minor] (`src/security/uploadValidation.ts`, `src/collections/Videos.ts` — `460e354`)**:
  - **Fix**: Removed the unused `120 MB` constant and unified the hard multipart stream cap on `MAX_VIDEO_REQUEST_SIZE_BYTES = 105 * 1024 * 1024` (105 MB, matching the planned Phase 6 Nginx `client_max_body_size 105m` for `/api/videos`, giving 5 MB headroom above the 100 MB `MAX_VIDEO_FILE_SIZE_BYTES` file limit for multipart headers/fields).
- **R-6 [minor] (`src/env.ts`, `src/env.test.ts`, `.env.example`, `src/collections/Videos.ts`, `tests/int/p2-t2.int.test.ts` — `460e354`)**:

Added unit tests in `src/env.test.ts` (including rejecting `VIDEOS_DIR` inside `MEDIA_DIR`) and an integration test in `tests/int/p2-t2.int.test.ts` proving `GET /api/media/file/videos%2F<filename>` returns `400`/`404` and cannot reach video files.
- **R-7 [minor] (`src/collections/Materials.ts`, `tests/int/p2-t2.int.test.ts` — `460e354`)**:

Tested in `tests/int/p2-t2.int.test.ts` with `brands: [999999]`.

    2. **Scoped `/api/videos` multipart endpoints (`src/collections/Videos.ts` — `createVideoUploadEndpoint`)**: Checks `isAdminOrEditor({ req })` before touching the request body stream (`R-2`), then wraps Payload's built-in `POST /`, `PATCH /`, and `PATCH /:id` endpoints on `videos` with `Object.create(req.payload)` overriding `config.upload` with `limits.fileSize: MAX_VIDEO_FILE_SIZE_BYTES` (`100 * 1024 * 1024`, 100 MB), `requestSizeLimit: MAX_VIDEO_REQUEST_SIZE_BYTES` (`105 * 1024 * 1024`, 105 MB hard stream cap matching the Phase 6 Nginx `/api/videos` limit, `R-5`), and `useTempFiles: true` (`tempFileDir: path.join(env.VIDEOS_DIR, '.tmp')`, `R-2`). *(Note: `next.config.ts` does not need `experimental.proxyClientMaxBodySize` because `src/proxy.ts` excludes `/api/*` via its matcher — corrected in Round 2 per `R-4`.)*
