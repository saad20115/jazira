- **R-11 [major] (`src/security/uploadValidation.ts`, `src/collections/Videos.ts`, `src/collections/Media.ts`, `tests/int/p2-t2.int.test.ts` — `64563d8`)**:
  - **Root cause**: Setting `tempFileDir: path.join(env.VIDEOS_DIR, '.tmp')` created a persistent `.tmp` directory inside `Videos.upload.staticDir` (`env.VIDEOS_DIR`), so `GET /api/videos/file/.tmp` caused Payload's `getFileHandler` to call `fs.readFile('<VIDEOS_DIR>/.tmp')` and fail with `EISDIR` (`ECONNRESET`), while in-flight temp files lived under `staticDir`.
  - **Fix**:
    1. Moved `VIDEO_UPLOAD_TEMP_DIR` outside `env.VIDEOS_DIR` and `env.MEDIA_DIR` to `path.join(os.tmpdir(), 'aljazira-video-uploads')`, with an isolated per-request subdirectory `path.join(VIDEO_UPLOAD_TEMP_DIR, '<timestamp>-<random>')` that is recursively removed (`fs.rm(..., { recursive: true, force: true })`) in `finally`.
    2. Added `createSafeUploadFileHandler(staticDir)` in `src/security/uploadValidation.ts` and registered it in `Videos.upload.handlers` and `Media.upload.handlers` so any request with `/` or `\` or a leading `.` (e.g. `.tmp` or `videos%2F...`) or any path that is not an existing regular file returns HTTP `404` immediately.
  - **Tests**: Verified in `tests/int/p2-t2.int.test.ts` that `VIDEO_UPLOAD_TEMP_DIR` is outside `VIDEOS_DIR` and `MEDIA_DIR`, that `.tmp` does not exist inside `VIDEOS_DIR`, and that `GET /api/videos/file/.tmp` returns HTTP `404`.
- **R-12 [major] (`src/collections/Videos.ts`, `src/security/uploadValidation.ts`, `tests/int/p2-t2.int.test.ts` — `64563d8`)**:
  - **Root cause**: `createVideoUploadEndpoint` set `limits.fileSize` without `limits.files: 1`, and only cleaned up `req.file?.tempFilePath` in `finally`. Sending a second file part (`file2` or two `file` fields) caused Busboy to write temp files that were not in `req.file` and were left on disk if validation failed.
  - **Fix**:
    1. Added `files: 1` to `limits` in `createVideoUploadEndpoint` so Busboy rejects any multipart request containing more than 1 file part with HTTP `413` (`Multipart limit has been reached`).
    2. Added `collectRequestTempFilePaths(req)` in `src/security/uploadValidation.ts` to inspect both `req.file` and all entries in `req.files` (single or array), plus recursive cleanup of the per-request `requestTempDir` in `finally`, guaranteeing zero leaked temp files whether the request succeeds, fails validation, or hits a multipart limit.
  - **Tests**: Verified in `tests/int/p2-t2.int.test.ts` by sending both `file` + `file2` (`413`) and two `file` parts (`413`), and asserting that `VIDEO_UPLOAD_TEMP_DIR` contains `0` leftover entries afterwards.
- **R-13 [minor] (`src/collections/Videos.ts`, `src/payload.config.ts`, `tests/int/p2-t2.int.test.ts` — `64563d8`)**:
  - **Root cause**: Busboy triggers `file.truncated = true` (`File size limit has been reached`) when the stream reaches `limits.fileSize` bytes (`>=`), rejecting an exact `100 MiB` (`104,857,600`-byte) file at the boundary.
  - **Fix**: Set Busboy's `limits.fileSize` to `MAX_VIDEO_FILE_SIZE_BYTES + 1` (`104,857,601` bytes) in `src/collections/Videos.ts` and `MAX_MEDIA_FILE_SIZE_BYTES + 1` (`10,485,761` bytes) in `src/payload.config.ts`, while `validateAndSanitizeVideoFile` / `validateAndSanitizeMediaFile` enforce `file.size <= MAX_VIDEO_FILE_SIZE_BYTES` / `MAX_MEDIA_FILE_SIZE_BYTES` inclusive.
  - **Tests**: Verified in `tests/int/p2-t2.int.test.ts` that an exact `100 MiB` (`104,857,600`-byte) MP4 succeeds with HTTP `201` (`filesize === 104857600`) while `100 MiB + 1` (`104,857,601` bytes) is rejected (`400`/`413`).
- **R-14 [minor] (`src/security/uploadValidation.ts`, `src/collections/Media.ts`, `src/collections/Videos.ts`, `tests/int/p2-t2.int.test.ts` — `64563d8`)**:
  - **Root cause**: Payload's default `getFileHandler` throws a generic `APIError` (`500`) when `fs.readFile` fails with `ENOENT`, and url-decodes `%2F` before passing `args.params.filename`.
  - **Fix**: `createSafeUploadFileHandler(staticDir)` in `Media.upload.handlers` and `Videos.upload.handlers` rejects any `filename` containing `/`, `\`, or leading `.`, or any missing/non-regular file with HTTP `404` (`Response.json({ errors: [{ message: 'Not Found' }] }, { status: 404 })`). Tightened `tests/int/p2-t2.int.test.ts` to assert exact `expect(resCrossRead.status).toBe(404)`.

## Review findings (Round 1)
- **R-1 [major] (`src/security/uploadValidation.ts`, `src/security/uploadValidation.test.ts`, `tests/int/p2-t2.int.test.ts` — `460e354`)**:
  - **Root cause**: `validateAndSanitizeVideoFile()` validated the magic bytes and `file.mimetype` but left `file.name` untouched, so a valid MP4 uploaded as `clip.html`, `clip.svg`, `vpoly.html` (MP4 with `<script>` in a `free` box), or `noext` was stored with its attacker-supplied filename/extension.
  - **Fix**: Added `generateRandomizedVideoFilename(detectedMime)` deriving the stored extension **strictly from `detectedMime`** (`'video/mp4' → 'mp4'`, `'video/webm' → 'webm'`), ignoring the incoming filename/extension, and setting `file.name = '<timestamp>-<16hex>.<mp4|webm>'`.
  - **Tests**: Added unit assertions in `src/security/uploadValidation.test.ts` and integration tests in `tests/int/p2-t2.int.test.ts` uploading a valid MP4 as `clip.html`, `clip.svg`, `vpoly.html` (structurally valid MP4 containing `<script>alert(1)</script>` inside a `free` box with `Content-Type: text/html`), and `noext`, asserting that every stored filename matches `^\d+-[0-9a-f]{16}\.mp4$` and the file is served with `Content-Type: video/mp4`.
- **R-2 [major] (`src/collections/Videos.ts`, `tests/int/p2-t2.int.test.ts` — `460e354`, refined in `64563d8`)**:
  - **Root cause**: `createVideoUploadEndpoint` passed the request straight into Payload's `defaultEndpoint.handler(req)` (`addDataAndFileToRequest` → `processMultipart`), which buffered the entire 100 MB multipart body in memory before `createOperation`/`updateOperation` checked `isAdminOrEditor`.

    1. Added `if (!isAdminOrEditor({ req })) { throw new Forbidden(req.t) }` at the very top of `createVideoUploadEndpoint` **before** `defaultEndpoint.handler(req)` is called, so anonymous requests are rejected with `403` before a single byte of the body stream is read.

Configured `useTempFiles: true` with an isolated per-request directory under `VIDEO_UPLOAD_TEMP_DIR` (`path.join(os.tmpdir(), 'aljazira-video-uploads')`, outside `VIDEOS_DIR` per `R-11`) and `limits.files: 1` (`R-12`) on the scoped `videos` upload config so authorized 100 MB video uploads stream to disk via Busboy temp files instead of holding 100 MB `Buffer` chunks in Node heap, with `try / finally` cleanup of all `req.file` / `req.files` temp paths and the per-request temp directory.
  - **Tests**: Added an integration test in `tests/int/p2-t2.int.test.ts` passing a 99 MB `ReadableStream` (`highWaterMark: 0`) to `POST /api/videos` as an anonymous user, asserting `status === 403`, `req.bodyUsed === false`, `bytesReadFromAnonStream === 0`, and `elapsedAnonLargeMs < 500`.
