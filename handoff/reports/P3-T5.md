### Evidence — same output before and after
Method:
- I built a production build of the clean tree at `6a9a202` (before) and of the seam (after). Each
  build started from an empty `.next`.
- Each build was served with `next start -H 127.0.0.1 -p 3170` against the same p3t5 DB, with
  `arabicEnabled` on.
- `seam-proof.mjs capture` stores four things per locale:
  - the raw `/en` and `/ar` server HTML;
  - a normalized copy of that HTML;
  - the computed style (all properties, plus `::before`/`::after`) and the box of every element in
    section 4, at 1440×900 and 390×844 with DPR 1;
  - a section screenshot.
- Normalization removes only per-build or per-request tokens:
  - the CSP nonce;
  - the build id;
  - `/_next/static/…` file names;
  - the `<hash>_` prefix of CSS-module class names, and only inside `class="…"` attributes and RSC
    `className` strings.

**Control (method check):** I captured the same before build twice and compared it with itself:
0 changed lines everywhere, and 0 differing pixels
(`docs/reports/evidence/P3-T5/m1-seam/control-same-build-summary.txt`). The first control run found
a flaw in my method: Chrome lists CSS custom properties in no fixed order. I fixed the script to sort
the keys and re-ran both the before capture and the control. That first run is reported here; its
files were overwritten.
