  - **What Payload 3.91 already does vs what our `I5` hook adds**:
    - In `node_modules/payload/dist/uploads/checkFileRestrictions.js` (lines 336–353), Payload 3.91 calls `fileTypeFromBuffer(file.data)`. However, when `fileTypeFromBuffer` returns `undefined` (which happens for plain text, HTML, or script files that have no binary magic signature), Payload 3.91 **falls back to extension-based MIME detection** (`getFileTypeFallback(file.name).mime`), meaning a disguised HTML file renamed `disguised.jpg` passes Payload's built-in MIME check and reaches Sharp! Furthermore, in `node_modules/payload/dist/uploads/getSanitizedUploadFilename.js`, Payload preserves leading dots on filenames (e.g. `.hidden.jpg` → `.hidden.webp`).

      2. Inspects the raw magic bytes directly (`FF D8 FF` for JPEG, `89 50 4E 47 0D 0A 1A 0A` for PNG, `RIFF....WEBP` for WebP, `....ftyp(avif|avis|mif1|msf1)` for AVIF) with **no extension fallback**, rejecting `.svg` and disguised HTML renamed `.jpg` before Sharp or disk I/O runs, and overwriting `req.file.mimetype` with the magic-byte-verified MIME type.
      3. Sanitizes `req.file.name` via `sanitizeUploadFilename` (strips directory paths, control characters, unsafe characters, and leading dots).

### 2. A2 session-revocation check (requests + status codes)
In Payload 3.91 (`node_modules/payload/dist/auth/strategies/jwt.js` lines 110–116), when `auth.useSessions` is enabled (`true`), `JWTAuthentication` verifies the JWT signature and then looks up `authenticationReference.sid` inside `user.sessions`. When the session `sid` is removed (either by `POST /api/users/logout` or by an admin clearing `sessions: []` via `PATCH /api/users/:id`), `JWTAuthentication` returns `{ user: null }`. Consequently:
- Protected collection routes (`GET /api/users`) and token refresh (`POST /api/users/refresh-token`) reject the old token with HTTP `403 Forbidden` (`{"errors":[{"message":"لا يسمح لك القيام بهذه العمليّة."}]}`).
- `GET /api/users/me` with the old token returns `200 {"user":null,"message":"Account"}` instead of the authenticated user.

Verified sequence in `tests/int/p1-t3.int.test.ts` (lines 429–516):
```text
# 1. User login -> token1 issued with sid in users_sessions
POST /api/users/login {"email":"session@aljazira.co","password":"Strong!SessionPass#2026"}
-> 200 OK (Set-Cookie: payload-token=<token1>; Path=/; HttpOnly; SameSite=Strict)

GET /api/users (Authorization: JWT <token1>)
-> 200 OK (totalDocs: 1)

# User logs out -> session sid removed from users_sessions
POST /api/users/logout (Authorization: JWT <token1>)
```
