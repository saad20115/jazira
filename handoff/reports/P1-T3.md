### 2. A2 session-revocation check (`POST /api/users/logout` and `POST /api/users/:id/revoke-sessions`)
In Payload 3.91 (`node_modules/payload/dist/auth/strategies/jwt.js` lines 110–116), when `auth.useSessions` is enabled (`true`), `JWTAuthentication` verifies the JWT signature and then looks up `authenticationReference.sid` inside `user.sessions`. When the session `sid` is removed (either by `POST /api/users/logout` or by an admin calling `POST /api/users/:id/revoke-sessions`), `JWTAuthentication` returns `{ user: null }`. Consequently:
- Protected collection routes (`GET /api/users`) and token refresh (`POST /api/users/refresh-token`) reject the old token with HTTP `403 Forbidden` (`{"errors":[{"message":"لا يسمح لك القيام بهذه العمليّة."}]}`).
- `GET /api/users/me` with the old token returns `200 {"user":null,"message":"Account"}` instead of the authenticated user.

Verified sequence in `tests/int/p1-t3.int.test.ts` (lines 438–559):
