# P2-T1 report — round 1

## Done
- **Slug field factory & Arabic-to-Latin transliteration (`src/fields/slug.ts`, `src/fields/slug.test.ts` — `I1`)**:
  - Implemented `slugField({ from = 'title', name = 'slug', required = true })` returning a Payload `TextField` (`unique: true`, `index: true`, `admin.position: 'sidebar'`).
  - Built in-code Arabic → Latin transliteration table (`transliterateArabicToLatin`) and `slugify()` (stripping Arabic harakat/tashkeel `U+064B..U+065F`, `U+0670`, tatweel `ـ`, converting Eastern Arabic `٠-٩` and Extended Arabic-Indic `۰-۹` digits to ASCII `0-9`, normalizing Latin diacritics via NFKD, collapsing non-alphanumeric runs to single `-`).
  - Added `beforeValidate` hook that prefers the English source field (`title.en` or `originalDoc.title.en`, or string `title` when `req.locale === 'en'`), falls back to transliterated Arabic (`title.ar` or string `title`), preserves manual editor-supplied slugs (normalizing them via `slugify`), and resolves uniqueness collisions against `req.payload.find` (`baseSlug`, `baseSlug-2`, `baseSlug-3`, …).
  - Enforced `validateSlug` matching `^[a-z0-9]+(?:-[a-z0-9]+)*$`.
  - Unit-tested 10 real English titles from `design/copy/02-services.md` & `design/copy/04-projects.md`, 5 real Arabic titles with diacritics and Eastern Arabic digits, English preference, Arabic fallback, manual slug preservation, uniqueness collision resolution (`-2`, `-3`), and pattern validation (`19 passed` in `src/fields/slug.test.ts`).
- **Link field factory & scheme validator (`src/fields/link.ts`, `src/fields/link.test.ts` — `I3`)**:
  - Implemented `linkField()` returning a Payload `GroupField` with localized `label` (`ar` / `en`), `type` (`internal` | `external`), conditional `internalRoute` (`/`-prefixed path or route select), conditional `externalUrl`, and `newTab`.
  - Implemented `validateExternalUrl` (**I3**) parsing strictly via `new URL()`, stripping ASCII control characters and whitespace before scheme inspection, allowing only `http:`, `https:`, `mailto:`, and `tel:`, and rejecting `javascript:` (including mixed-case `JaVaScRiPt:` and control-character obfuscation `java\tscript:`), `data:`, `vbscript:`, `file:`, `blob:`, `ftp:`, protocol-relative `//evil.com`, embedded credentials (`https://user:pass@example.com`), and non-allowlisted hosts when `allowedHosts` is specified (e.g., `linkedin.com`).
  - Implemented `validateInternalPath` enforcing leading single `/`, rejecting protocol-relative `//`, schemes, and `..` traversal segments (`7 passed` in `src/fields/link.test.ts`).
- **Video URL field factory & embed helper (`src/fields/videoUrl.ts`, `src/fields/videoUrl.test.ts` — `I4`)**:
  - Implemented `parseVideoUrl()`, `toEmbedUrl()`, `validateVideoUrl()`, and `videoUrlField()` enforcing `https:` and the exact 5-host allowlist (`youtube.com`, `www.youtube.com`, `youtu.be`, `vimeo.com`, `player.vimeo.com`) parsed with `new URL()` (never regex on the raw URL string).
  - Normalizes accepted URLs in `beforeValidate` (`https://www.youtube.com/watch?v=<id>` or `https://vimeo.com/<id>`) and converts them via `toEmbedUrl()` to `https://www.youtube-nocookie.com/embed/<id>` or `https://player.vimeo.com/video/<id>`.
  - Tested and rejected `https://youtube.com.evil.com/watch?v=dQw4w9WgXcQ`, `https://evil-youtube.com/...`, `http://www.youtube.com/...`, `javascript:alert(1)`, embedded credentials, and malformed IDs (`4 passed` in `src/fields/videoUrl.test.ts`).
- **Manual sort order field (`src/fields/order.ts`, `src/fields/order.test.ts`)**:
  - Implemented `orderField()` returning a Payload `NumberField` (`name: 'order'`, `defaultValue: 0`, `index: true`, `admin.position: 'sidebar'`, step `1`).
- **Publishable versions config (`src/collections/_shared/publishable.ts`, `src/collections/_shared/publishable.test.ts`)**:
  - Exported `publishableVersions` (`drafts: { autosave: { interval: 800 }, schedulePublish: true }`, `maxPerDoc: 25`) and `publishableGlobalVersions` (`drafts: { autosave: { interval: 800 }, schedulePublish: true }`, `max: 25`) matching `docs/02-content-model.md`.
- **Cache revalidation hooks (`src/hooks/revalidate.ts`, `src/hooks/revalidate.test.ts`)**:
  - Implemented `createRevalidateAfterChangeHook`, `createRevalidateAfterDeleteHook`, `createRevalidateGlobalAfterChangeHook`, `buildCollectionTags`, and `buildGlobalTags` calling `revalidateTag(tag, 'max')` (per collection/global, per doc slug across `doc` and `previousDoc`, and per locale `ar`/`en`) and `revalidatePath(path)`.
  - Safely no-ops when called outside the Next.js request/cache runtime (CLI migrations, seed scripts, Vitest) and never throws into an editor's save (`4 passed` in `src/hooks/revalidate.test.ts`).
- **Publishable collection access test (`src/access/publishedOrLoggedIn.test.ts` — `Z2`)**:
  - Added a `fakePublishableCollection` (`versions: publishableVersions`, `access.read: publishedOrLoggedIn`) test proving anonymous callers receive `{ _status: { equals: 'published' } }` (selecting only published documents and excluding `_status: 'draft'`), while authenticated `editor` and `admin` users receive `true` (`4 passed` in `src/access/publishedOrLoggedIn.test.ts`).
